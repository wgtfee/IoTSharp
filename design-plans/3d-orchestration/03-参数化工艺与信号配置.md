# 工艺参数只填一次，自动关联动作与信号

日期：2026-11-05。Written against：`Develop / 4d3b7feb`。状态：待实施。

2026-11-06 补充：机器人取放与桁架码垛按 [05 自动规划 V2](05-机器人取放与桁架码垛自动规划V2.md) 的运动合同、交付与验收执行；本文件继续负责通用工艺参数和信号配置。

## Evidence chain

- Surface：工作台的“模板”、节点属性、工作点/姿态、对象数据绑定和组件 PLC 绑定。
- Problem：已有模板工厂接受参数，但界面调用不传参数；现有节点表单逐个选 Actor/工作点等引用，信号需要在两个面板衔接。部分通用模板包含真实三维运行器不支持的节点。
- Owner：`ClientApp/src/digital-twin/action-flow/components/ActionFlowDesigner.vue:74`；`action-flow/templates/index.ts:4–45`；`ActionNodeInspector.vue:7–22`；`components/ComponentPropertyPanel.vue:60–76,182–183,258–266`；`workbench.vue:493–519,1601–1606,2318–2366`。
- Evidence：生产工厂生成的机器人模板为 10 节点、0 Actor；工厂 policies 未指定 executionTarget；三维支持集位于 `action-flow/contracts/action-flow-v2.ts:19–23`，并非所有独立调试节点都可驱动三维。
- Design sources：工业编排平台 V2 的示教、Capability 和参数化模板章节，以及动作流 V1 的标准工艺模板章节。本方案将这些规划对接到当前已有实现。
- Scope：标准工位为首个闭环，随后机器人取放与桁架码垛；共享 Action Flow、Manifest 和绑定合同。
- Uncertainty：不把模板生成成功等同于设备能安全运动；还需真实三维模拟、数据保存发布和针对真实设备的独立联调。

## Design decision

在现有编辑器上增加“工艺参数 → 完整动作图”的配置层。参数化模式生成的仍是显式 Action Flow V2 节点与边，编译后由原运行器执行。它不是另一个调度器，也不依赖前端隐藏变量维持行为。

模板选择前就明确用途：三维模拟、独立图调试、服务端真实执行。缺乏适配的模板不出现在错误运行目标的可选列表里。

## Reuse

- `ActionFlowTemplateOptions` 和现有五类模板工厂；复用参数机制，不直接把所有旧模板切为 scene。
- `presets/DrawingPackagingActionFlows.ts` 中工位到位、加工、标记、放行的行为示例；先抽取参数合同，去除图纸专用 ID、组名及固定布局后才能通用化。
- `ActionFlowValidator`、`ActionFlowCompiler`、`SceneActionFlowRuntime` 及服务端编译/运行服务。
- `TwinOrchestrationDesigner.ts` 的 WorkPoint / MaterialSlot / ToolFrame / Pose 定义操作。
- `workbench.vue` 已有 capturePoseFromRuntime，`TwinRuntime` 的 captureActuatorPose，作为示教读取能力起点。
- `ComponentBindingResolver`、`BindingValueTransform` 和组件 bindingSlots。
- 拟新增 `action-flow/components/ActionFlowTemplateWizard.vue`、`action-flow/templates/TemplateParameterResolver.ts` 与 `bindings/BindingTable.vue`。现有逐节点属性面板没有覆盖“为一组节点填写一次参数”和“同时查看工位信号集合”的职责。

## Changes

### 1. 参数向导

Owner：ActionFlowDesigner 的 addTemplate、模板工厂、工作台工艺入口。

四个页面：

1. **选择工艺**：默认带入当前设备，按组件能力显示可用工艺与运行目标。
2. **配置资源**：来源、目标、工具、工作点、数量；普通工位只显示必要的到位组、加工时间、完成阶段。
3. **确认条件**：适用的联锁与信号；模拟输入和真实反馈分开标注。
4. **预览结果**：高亮涉及设备、物料位和路线，显示可读步骤摘要、待配置项及将新增/复用的定义。

匹配顺序固定为：用户显式选择 → 已声明语义且唯一兼容的资源 → 待配置。多个候选不能自动取数组第一项；仅名称相似不构成正确映射依据。

确认后在一个编辑事务中创建或复用定义并生成节点/边。取消向导不留下半组节点。未完成可以保存为待配置草稿，不能标为可运行。

### 2. 首批工艺模板及边界

| 顺序 | 工艺 | 用户填写 | 已有执行基础与必要适配 |
| --- | --- | --- | --- |
| 1 | 普通加工工位 | 执行设备、到位批次/完成组、加工时间、完成阶段 | 参考 WaitStation → Delay → MarkMaterial → CompleteStation。只在工位和运输配置已具备时生成；同设备同完成组只能有一个负责放行的启用流程，防止和旧工位定时逻辑重复驱动。 |
| 2 | 机器人取放 | 执行设备、来源槽、目标槽、工具、目标/姿态约束、数量、速度、许可 | 引擎生成轨迹；V2 的 FollowTrajectory 支持链完成后用于新工艺，交接复用现有原语。旧 Pick/Place 保持兼容，不把规划结果交给旧终点运动冒充路径执行。 |
| 3 | 桁架码垛 | 轴/工具能力、取料/托盘基准、行列层、中心距/层距、批量、搬运约束、隔板与换托 | 复用 stackPattern、工具轴和工作点；按受限动态策略生成本批轨迹，验证双工具、隔板和满托。详见 [V2 桁架与执行规则](05-机器人取放与桁架码垛自动规划V2.md)，不复制图纸专用坐标。 |
| 后续 | 岔口分流/空托回流、PLC 握手 | 物料条件、有效出口、信号及权限 | 三维路线和真实命令模板分开。当前 ReserveSection 等独立节点不可直接当作三维实现，需按支持合同适配并单独验收。 |

不新增“假完成”或跳过安全条件的便捷节点。所有模板都要有用途、版本、所需能力、参数定义、可用运行目标和示例。

### 3. 参数视图与高级图编辑保持一致

Owner：模板工厂、ActionFlowDesigner、动作定义合同。

- 一个流程只有一份可执行节点/边。模板实例元数据只记录 templateKey、templateVersion、参数映射、生成节点归属和生成基线 hash；它不直接驱动执行。
- 通过版本化、可选合同扩展保存模板元数据；前后端 schema/编译器共同认可，现有流程缺少元数据时仍按自定义图处理。
- 未更改结构的模板实例可反复编辑参数，更新原节点而不换掉所有稳定 ID。
- 用户改动受模板管理的结构后标为“已自定义”。简易面板显示摘要；重新应用模板必须给出差异并要求明确选择，不能覆盖高级修改。
- 编辑坐标、缩放或布局不应把模板标为业务结构自定义，也不应改变执行 hash。
- 升级模板只对当前草稿显式执行；不可自动重写已发布版本和已有场景。

### 4. 原位工作点与示教

Owner：工作台已有工作点/姿态方法、ThreeJsEditorHost、运行 adapter。

机器人取放与桁架码垛的专门轨迹规划见 [05 自动规划 V2](05-机器人取放与桁架码垛自动规划V2.md)。默认使用预设目标由引擎生成接近、抬升、搬运与回撤，示教和必经姿态作为修正。桁架增加托盘基准、配方、隔板及换托。现有 MoveTo 不应标成已具备工具直线和规划产物执行能力。

- 在来源/目标参数旁提供“在 3D 中选择 / 记录当前位置 / 新建工作点”，完成后返回原向导并保留已填数据。
- 普通点击模型表面不是已验证的机器人姿态：必须区分世界坐标、设备局部坐标、TCP 和轴目标。
- 复用 captureActuatorPose；示教模式显示只读真实反馈或可操作仿真轴，不能通过拖动示教暗中向 PLC 发运动命令。
- 记录前确认轴、单位、局部变换、工具归属和行程；仿真试跑提供接近/回撤与交接结果。
- 已有机器人内部关键节点路径由组件能力声明或模型节点选择产生；高级用户仍可手工配置，普通工位向导不要求输入路径。

### 5. 工位信号表

Owner：工作台 binding-form/list、ComponentPropertyPanel bindingSlots、BindingValueTransform。

一行一个业务信号，包含：角色、设备、点位、数据类型/单位、转换后样值、质量/更新时间、当前消费者、校验结果。

- 组件已有声明的 slots 自动列出；用户直接在相应行选择 Device 和 Key，创建/更新同一 bindingId 并关联 slot，免去先去另一个面板创建 routeEvent。
- 最新遥测 Key 作为可选项；未上报 Key 可手工输入并明确标为尚无样值，不能伪造已接通。
- 设备来自当前授权范围；Product 是能力模板，Device 是实际数据源，不把资源模型或业务 Asset 当作 Device。
- 轴位置显示原始值、换算公式/单位和预览结果，复用已有转换合同；需要合同扩展时前后端一致支持后才显示该选项。
- 改 Key/设备保持 bindingId；涉及类型变化时逐一列出不兼容消费者，避免自动改坏路线或动作条件。
- 批量应用以明确角色映射为依据，先展示所有目标设备的匹配表；缺失或重复的点位留待处理。不得按列表顺序猜测设备身份。
- 第一阶段批量仅用于相同能力模板的工位；跨设备类型的整线克隆后续独立交付。

### 6. 试运行与结果

Owner：已有 SceneFlowRuntimePanel、ActionFlowDebugger、工作台控制函数。

- 先显示当前真实支持的整线模拟与单路线测试。新模板生成后暂停旧预览并要求按最新配置重新运行。
- 结果展示当前步骤、等待原因、来源/目标库存、工位放行和故障；失败直接返回参数或节点字段。
- 首期不承诺三维单工位隔离运行。后续若实施，须显式提供上下游物料/信号夹具且仅限仿真，不能隐藏依赖后宣称整线已验收。
- 独立图调试成功不代表真实三维交接正确；真实三维成功也不代表 PLC 命令或数据库发布成功。

## Scope

- Inherit：工艺向导、参数视图、标准信号表与生成的同一 Action Flow。
- Verify：专业节点编辑、旧 Behavior 与已有 V3 场景、手工路线、GLB/参数化组件、已发布版本重放、2D 使用同一 Manifest。
- Exclude：新语言、新调度器、任意脚本、PLC 自动写入、完整模板市场。
- Motion：机器人/桁架自动规划由 V2 专门规定；本文件不重复定义算法和运动验收。

## Validation

产品任务与预期结果：

1. 选现有工位并填写加工时间/完成阶段，生成流程无需手填 ID/JSON；可保存重开并在三维按该时间加工后放行。
2. 两台机器人存在同名工作点，系统不会误绑；来源槽允许位于另一台设备，工具/轴必须属于 Actor。
3. 模板生成后的普通参数修改保持节点 ID；高级结构修改后不会被参数视图覆盖。
4. 改同一信号的 Key，工位 slots、动作条件和所有路线引用保留；批量换绑不匹配的设备明确留空。
5. 不同模板运行目标正确；当前三维不支持的节点被预先拦截，不能仅在运行时报错。
6. 模板一次生成可一次撤销；取消向导不污染 Manifest；保存/发布/重开后语义不依赖前端向导内存。

实施后从 `ClientApp` 执行：`npm run typecheck`、`npm run build`、`npm run verify:scene-action-flows`、`npm run verify:material-interactions`、`npm run verify:motion-limits`、`npm run verify:flow-safety`。新增参数化工位与模板版本往返测试，使用实际生产校验器和三维运行器，不用假的“设备完成”代替交接结果。

如果修改动作或绑定合同，补充后端 `DigitalTwinManifestInspectorTests`、`DigitalTwinSceneServiceTests` 和 `TwinActionFlowRuntimeServiceTests`。浏览器任务测试、数据库往返和真实设备联调分别记录。

## Stop conditions

- 组件没有足够的能力、工作点或工具声明时，向导停在待配置并指出缺项；不能用任意坐标/默认工具自动放行。
- 模板含当前执行目标不支持的节点时，先完成适配验证或限制用途，不能靠切模式绕过。
