## 1. 评审结论与产品目标

R3 总体合理，可以作为 V2 的修订输入，但不宜原样定稿。应保留执行链、逻辑时间、机构能力边界和验证分级；修正碰撞依赖范围、轨迹复用与发布条件；把基础工艺卡及完整码垛验收保留在首期功能范围内。

核心用户流程继续保持：

**选择设备和工具 → 选择来源与目标或码垛配方 → 自动生成步骤和轨迹 → 查看预览与检查结果 → 保存工艺。**

用户不应为了完成普通取放任务，逐段配置动作节点、手填内部 ID，或者理解轨迹摘要、求解器预算和碰撞细分参数。底层严谨性由模型、模板、执行链与校验机制承担。

首期覆盖内置机械臂已确认的能力范围和当前图纸桁架轴布局。取放位置由已配置的工作点、工具 TCP、物料抓取关系和托盘坐标确定；场景引擎据此计算目标与轨迹，不从任意模型外观自行认定可用抓取面。

## 4. 必须修正的六项内容

### 4.1 基础工艺卡留在 M1，整托工艺能力留在 M3

R3 §11.1 把“工艺展开”列入 RM-A，同时包含现有取放和规则码垛模板。这样可能使首期只具备轨迹执行，用户仍须手工组装动作图，偏离减少编排操作的目标。

修订为：M1 提供机器人取放与桁架码垛的基础工艺卡，把选择的设备、工具、目标和配方转换为同一动作图中的步骤与引用。M2a 接通实际轨迹和物料交接，M2b 完成可发布仿真。通用工艺生成和任意流程组合放入后续路线图。

工艺卡仅是权威动作图及既有目标定义的编辑视图，禁止保存第二份可独立修改的流程。自动生成的节点能映射回工艺步骤；重新生成应保护用户明确修改的部分，不静默覆盖。

M3 必须保留双工具互锁、全部层、隔板、满托换托和中断恢复。基础暂停、继续、故障后的重新核对属于当前任务能力；完整持久化检查点、任意时刻恢复及历史分支属于后续能力。

### 4.2 规划依赖范围纳入最小净空和误差

R3 §6.2 将依赖范围定义为路径扫掠包络按 `δ_res` 扩大，§6.4 又规定始终在范围外的对象不使产物失效。仅凭此条件会漏掉影响最小净空的障碍。

示例：业务最小净空为 50 mm，验证分辨率为 1 mm，某障碍距离机器人扫掠边界 10 mm。障碍不在扩大 1 mm 的范围内，却违反 50 mm 净空要求。这些数值只用于解释问题，不作为产品默认值。

建议规则：

1. 空间依赖范围覆盖机器人所有受检链接、工具和持料的完整扫掠几何，并扩大最小净空、模型/变换误差及所选验证方法需要的额外保守余量。若包络本身为近似，还须覆盖包络近似误差。
2. 来源点、目标点、参考坐标及其父级变换、托盘身份、工具、配方、物料、相关工位与联锁保持显式依赖，不以是否与扫掠几何相交决定其必要性。
3. 路径范围内对象变化、新对象进入范围、父级变换引起子对象进入范围，都能使相关结论失效。只监听已有依赖集合无法发现新进入对象，应结合空间索引或场景变更查询。
4. 量化后的摘要相同不能替代实际偏差检查。量化及实际变化必须处于已计入的误差预算内。
5. 区分“产生新路径所用的搜索输入”和“复用既有路径所需的验证依赖”。局部依赖可以减少无关失效，但不能据此隐去重新规划所需的输入与版本。

### 4.3 补全碰撞判据，验证最终执行曲线

R3 §5 的 `d_max = Σ |Δq_j| × R_j` 可作为限定模型与插值下的保守位移上界。`R_j` 必须覆盖整个区间内的几何位置，包括工具、持料及下游平移轴的可能伸展；角度使用弧度，长度统一单位。

建议将“记录了净空和误差”提升为实际通过条件。对于已证明位移上界有效、并检查两端的区间，可采用以下形式的充分条件：

```text
min(区间起点间距, 区间终点间距)
    > 业务最小净空 c_min + 相对位移上界 D / 2 + 误差预算 ε_pair
```

其中，静态障碍场景的 `D` 为机器人相关几何的运动上界；自碰撞或已建模运动障碍取双方相对运动的保守上界。`ε_pair` 包含该检测对尚未由几何膨胀覆盖的模型、变换量化及数值误差，避免漏计或重复计入。该条件是待实现并验证的充分条件，不代表本文已完成算法证明或碰撞验收。

实施约束：

- 检查完整几何，不能仅检测 TCP 和两个端点是否直接相交。
- 最终插值若为样条或经过平滑处理，应使用该曲线的区间运动界；仅增加采样点不自动形成连续区间保证。
- 不能为了简化碰撞上界，采用时间上的分段线性轴位置后，仍宣称已经满足有限加速度或速度连续性。时间参数化、转角处理和碰撞验证必须针对同一最终表示。
- 保守膨胀相交而未证实真实碰撞时，报告“未能验证通过”或“不确定”；细分后可以通过，但不能减少覆盖、放宽净空来获得通过。
- 工具与工件、工件与支撑面的允许接触，按动作阶段和指定碰撞对配置；接触豁免不扩大到整个工具、整段搬运或无关障碍。
- 抓取后工件进入持料几何；释放后进入场景占用/障碍集合，影响随后运动和垛顶高度。
- 运动障碍没有明确时间模型时标记不支持，不假定静止后判通过。

外部依据仅用于说明工程边界：OMPL 官方说明离散检查可能遗漏采样间的无效状态；MoveIt 官方说明部分时间参数化处理会改变几何路径，可能需要追加碰撞检查。这两项资料不替代本项目具体上界和误差预算的验证。[OMPL](https://ompl.kavrakilab.org/core/stateValidation.html)、[MoveIt](https://moveit.picknik.ai/main/doc/examples/time_parameterization/time_parameterization_tutorial.html)。

### 4.4 区分整托表索引、运行绑定和复用判定

R3 §7.2 的“配方 ID＋层号＋批号＋工具＋托盘变换”不足以唯一定位运动段。同一批存在接近、下降、抓取后抬升、搬运、放置及撤离，必须能区分节点或阶段。

建议采用三层信息：

| 层次 | 内容 | 作用 |
| --- | --- | --- |
| 条目索引 | 配方及版本、层、批、动作节点或运动阶段、工具引用 | 查找候选轨迹 |
| 运行绑定 | 本次来源与目标身份、坐标、起始轴状态、持料及抓取关系、占用、相关环境与模型版本 | 判断候选是否适用于当前任务 |
| 产物与报告 | `policyDigest`、`runPlanDigest`、`artifactHash`、求值器版本、验证报告 | 区分发布策略、本次输入和实际执行产物 |

复用逐项检查：起点连续性、目标放置误差、接触条件、物料规格与数量、抓取变换、工具、占用、环境依赖及剩余碰撞余量。表键命中只是找到候选，不等于可以执行。

托盘旋转误差必须按几何半径转换为位移；R3 的小角近似可以保留，并明确适用范围。用于误差吸收的碰撞余量应是已扣除业务最小净空和既有误差预算后的剩余量，不能把全部间距重复使用。

已存关节轨迹不会因托盘移动而自动平移。若实际偏差超出已验证容差，需重新生成并验证相关轨迹，或者拒绝；不能只移动显示路径。

规则码垛优先评估整托预生成，同时允许发布时明确选择的按批生成或逐步缓存策略。固定轨迹表模式下，配方要求执行的任一条目失败，发布失败；不能临时切换成动态模式掩盖失败。受限动态策略必须预先声明，生成发生在允许的停止边界，接受结果前再次核对当前状态。

### 4.5 消除阶段发布矛盾，保留 V2 验收底线

R3 §3.4 和 AC-01 要求 M0-S 完成“保存 → 发布 → 重开”，而 §2.3、S6 要求完整检查后才可发布。应拆开两类验证：

- M0-S：验证草稿保存、产物序列化、加载重开，以及隔离测试中发布链路的合同往返。测试构造器不得成为普通产品入口；正式发布仍拒绝 `testOnly`、未知版本和缺少必要检查的产物。
- M2b：验收正常产品入口的发布、重开和执行，检查结果与对应版本、产物及适用范围一致。

M0-S 的暂停和联锁用例必须有运动求值前的最低限度保护；M2a 再完成输入采样、联锁、运动、交接和事件提交的完整顺序。不能把最低限度保护一并拖到后续阶段。

R3 AC-01—AC-22 作为补充，不直接替换 V2 V01—V20。基础草稿、目标类型转换、锁定约束、取消与撤销、速度/加速度、机构能力、隔板、换托和恢复仍须验收。合并时为每一项保留来源、阶段和结果，不能因为更换编号丢失要求。

M0-S 的手写轨迹生成器可以不进入产品，但建议保留为明确标记的测试夹具，持续回归执行链，不必删除全部构造代码。

### 4.6 将验证复杂度留在模板和引擎层

保留 `testOnly → candidate → verified`，明确责任及变更触发条件：

| 角色 | 主要操作 | 不应承担的日常负担 |
| --- | --- | --- |
| 模板维护者 | 配置机构能力、工具、碰撞体、参数范围，关联验证记录 | 不把未经验证的占位值作为默认值分发 |
| 任务编辑者 | 选择设备、工具、来源、目标或配方，调整允许项，查看结果 | 不必逐段拼运动节点或反复确认底层模型版本 |
| 引擎与校验器 | 判断任务是否处于适用范围，维护依赖、失效、产物和报告 | 不把技术校验全部转为用户勾选确认 |

模板验证记录可在其声明范围内复用。每个任务仍自动检查具体输入和轨迹；超出范围、修改锁定约束或关键依赖变化时，再提示重新验证或选择适配模板。

R3 §2.3 的“已验证运行：无警示”改为“仿真检查通过，可查看覆盖范围”。正常通过不需要制造警报，但仍保留可查看的检查对象、精度和适用边界；现场验证单独命名。

## 5. 修订后的交付顺序

| 阶段 | 交付重点 | 退出条件 |
| --- | --- | --- |
| M0 | 合同、能力范围、参数来源、控制入口与最小草稿保存 | 引用和版本可往返，缺项明确，旧版本语义保持 |
| M0-S | 已知定时轨迹贯通编译/加载/求值/轴写入，暂不依赖自动规划 | 相同逻辑时刻轴值一致；最低限度暂停/联锁有效；每轴唯一有效写入者；正式发布拒绝测试产物 |
| M1 | 基础工艺卡、目标设置、走廊/直线生成、取消与撤销 | 普通取放无需手工逐段组图；生成结果标明几何预览及未完成检查 |
| M2a | 时间参数化、完整执行顺序、真实仿真物料交接、同源预览 | 机器人固定取放和桁架一层可试运行；配置、可解、时间/轴和交接要求满足；碰撞未完整检查明确标识且不可发布 |
| M2b | 最终曲线碰撞、完整依赖失效、验证配置与正常发布 | 四项检查及时间/轴约束通过；同一产物保存、发布、重开和执行一致 |
| M3 | 全部层、双工具、三种隔板、满托换托、基本恢复、整托表或声明的按批策略 | 完整码垛工艺通过，不能仅凭缓存命中或轨迹表生成完成验收 |
| M4 | 已声明机械臂能力内的自由空间自动绕障 | 最终产物重验证，接触段约束保持，预算与失败明确 |
| M5 | 具体设备适配、标定、控制器任务与反馈 | 单独现场验收，仿真结论不替代设备结果 |
| RM-A/RM-B | 独立运行状态、完整检查点、通用工艺扩展、分支推演及历史对照 | 独立定义等价性与证据，不挤占基础工艺卡和当前任务恢复 |

首个端到端验收单元仍采用“一个机器人固定取放＋一个桁架单层”，覆盖 M0—M2b。M3 扩展为完整整托。这样可以先交付可验证的小场景，再扩展工艺规模；M0—M3 不必捆绑成一次交付。
