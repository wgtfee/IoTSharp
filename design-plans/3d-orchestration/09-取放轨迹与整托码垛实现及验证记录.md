# 取放轨迹与整托码垛实现及验证记录

更新日期：2026-11-14。承接 07 实施方案及 08 第一批记录。本文区分源码实现、合成场景回归、浏览器、真实数据库与现场设备证据，不能把其中一项当作其他项的验收。

## 1. 当前可以做什么

在三维工作台编辑模式打开“取放工艺”，选择来源、目标和工具。已有模板声明时，不需要逐个手建预取、接触、退出、预放等工作点。缺少声明时，维护者在“模板取放声明”补充工具相对槽位的抓取关系、法向和接近/退出距离；不会根据模型外观猜坐标。

可以先预览世界位置，再填写实际轴的速度、加速度、加加速度，生成限于仿真的定时轨迹。保存后加入原有动作图，新工艺默认停用。工艺应用保留编辑器持有的场景引用，并记录应用前后的撤销历史。

启用物料交接后，可生成静态单批工艺，或保存按批次规划工艺。每批开始时绑定实际物料与托盘；在接近、夹紧、抓取、搬运、释放、撤离之间，继续使用原动作图调度和轴所有权，不增加第二套调度器。

桁架支持整层批次、完整托盘以及同一设备的独立隔板工具。8 层配方有 0、7、8 张隔板三种策略。高级恢复入口可从已完成整层继续，或先补最后一个已完成主物料层的隔板。恢复不生成替代库存，不移动已放好的物料。

### 2.1 冻结与失败处理

- 场景声明、对象变换、工具、执行轴、路线、绑定、联锁等依赖变化，会使旧轨迹失效。这里的 JSON 摘要是变更比较依据，不是加密签名或发布授权。
- 定时轨迹每次写入下一轴帧前都会重算场景声明摘要；声明在运动中变化时，在后续轴写入前停止并要求重新规划。此检查覆盖 manifest 声明，不代表对外部场景模型实时位移或新障碍的连续监控。
- 动态槽位绑定确切托盘身份与层位。成组载体朝向/缩放不一致时拒绝共同抓取姿态；不采用第一个载体的朝向掩盖其他载体。
- 来源物料的旋转、归属或身份在取料前改变，下一次轴写入前停止，不仅比较中心位置。
- 整托流程期间不能更换托盘。新工艺启动前，夹具挂有上一工艺物料时拒绝重新规划。
- 缺少真实场景执行适配器时，轨迹和批次节点不能退化为计时成功；改变步骤顺序也会失败。
- 同名工艺或遗留分段轨迹不会被覆盖。保存的规划记录包括所选候选、拒绝原因和检查范围；动态运行快照保留最近 128 个批次记录。它尚不是服务端持久审计日志。

### 2.2 连续碰撞初查的准确范围

当前对同段纯直线轴组合做连续包围体检查；对同段只有一个旋转轴变化且其余轴固定的部分，使用该关节整周圆柱包络进行更保守的初查。直线轴通过相对位移的三个区间求交检查完整连续段，不依赖固定时间采样；旋转轴采用全角度包络，可能拒绝实际可行路径。薄障碍位于两个端点之间时也能被发现。

检查工具/机构网格与已加载环境，以及保留抓取关系的物料扫掠。抓取前、释放后的本批库存仍参与对应阶段检查。编辑器网格和辅助标记不作为工艺障碍。

包围盒交叠表示该候选不能证明净空，可能保守拒绝；不是精确网格穿透结论。无冲突也仅表示已检查范围内未发现冲突，界面状态为部分检查，不能升级为完整碰撞通过。以下仍未实现：

1. 旋转轴与直线轴同段组合运动、多个旋转轴同段运动、全部机构自碰撞、双工具相互碰撞。
2. 标定误差、模型误差、工艺净空公差、对象对和阶段限定的接触豁免。
3. 蒙皮/实例/形变网格的完整支持及模型覆盖率证明。
4. 对新进入障碍的持续监控、空间依赖失效闭环和服务端验证证书。
5. 自动绕障；目前只在预先声明的候选间回退，不生成绕障路径。

因此 `validation` 继续保持 `simulation-only`，正式发布保护没有放开。

### 2.3 恢复与换托的准确范围

恢复入口要求完整层边界，可填写已完成主物料层数以及最后一层是否待补隔板。运行开始时核对实际物料/隔板数量、库存计数、配方层位和空夹具；伪造计数不能越过检查。测试确认恢复后既有物料身份和世界位姿保持不变。

这里不包含任意半层恢复、持料中自动恢复、断电现场恢复或整条输送线的自动换托调度。满托后需通过既有载体/工位绑定得到明确空托盘，下一份工艺才可重新规划；完整自动换托链仍待集成验收。

### 3.1 复现命令

在 `ClientApp` 执行：

```powershell
npm run verify:slot-tool-targets
npm run verify:pick-place-planning
npm run verify:flow-safety
npm run verify:material-interactions
npm run verify:motion-limits
npm run verify:scene-action-flows
npm run typecheck
npm run build
```

先运行规划回归生成临时产物，再在仓库根执行服务端往返：

```powershell
dotnet run --project ClientApp/scripts/drawing-contract-smoke/DrawingContractSmoke.csproj -- ClientApp/public/digital-twin/templates/drawing-0911-process.scene.json "$env:TEMP\iotsharp-pick-place-contract-fixture.json" "$env:TEMP\iotsharp-batch-planning-contract-fixture.json" "$env:TEMP\iotsharp-stacking-recipe-contract-fixture.json"
dotnet build IoTSharp/IoTSharp.csproj --no-restore -v:q
```

浏览器回归需要本机 Edge 和 Playwright。默认复用用户目录 `.ccpulse/e2e/node_modules/playwright`；其他环境通过 `MOTION_PLAYWRIGHT_PATH` 指定现有 Playwright 包路径。没有给业务依赖安装浏览器测试包。

```powershell
# 终端一，ClientApp
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5186 --strictPort
# 终端二，ClientApp；默认使用 /iot/scripts/browser/pick-place.html
npm run verify:pick-place-browser
```
