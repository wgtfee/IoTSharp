# 机器人取放与桁架码垛方案 V2 修订建议：自动轨迹规划取向

日期：2026-11-06。针对对象：《机器人取放与桁架码垛编排完整方案 V1》（2026-11-05，核查基线 `Develop / 4d3b7feb`）。

说明：本文只基于 V1 文档本身整理，**没有核对源码**。凡涉及现有实现的判断（例如内置求解器能约束哪些自由度），均标注为"待核实"。文中的参数数值是占位初值，不是从你的系统测得的结论。

## 0. 摘要

V1 的边界意识、单一真相源和仿真/真机隔离都做得对，建议原样保留。需要改的有三件事：

1. **取向调整**：从"用户逐点示教 → 手工加途经点"，改为"用户给语义目标 → 引擎生成并检查轨迹 → 示教降级为覆盖手段"。V1 把全自动避障排除在首期之外，这与你"让引擎自己处理轨迹"的目标冲突。
2. **补四处缺口**：点位的权威来源、求解器能力与"完整工具位姿"承诺不匹配、隔板策略与现有合同不一致、旧 Pick 参数不生效的处理策略。
3. **整理结构**：把三套里程碑编号（W / A–D / G）合并为一套，把散落的"不能……"整理成一份不变量清单，并按规划器分档重排交付顺序。

建议的最小可行第一刀见第 11 节。

## 1. 评审结论：保留什么、改什么

### 1.1 建议原样保留

| 内容 | 原因 |
| --- | --- |
| 单一可执行真相：动作流 V2，专用视图编辑同一批节点（§6） | 避免出现第二套引擎和第二份会漂移的数据 |
| 关节目标以 Pose 为准（§3） | 防止 XYZ 与关节两份目标互相矛盾 |
| 验证状态拆成四项且可过期（§5） | "配置完整 / 运动可解 / 碰撞检查 / 交接模拟"含义不同，不应合并成一个绿灯 |
| 仿真、实时监视、真实执行三种模式隔离（§7） | 浏览器计算的轨迹不应直接下发真机 |
| 版本化合同、旧版本语义不变（§4、§6.1） | 已发布流程不能被静默改动 |
| 路径样本与检查结果是"派生缓存"，不是编辑真相源（§6.1） | 这条正好是自动规划需要的归属，V2 只需补细节 |

### 1.2 建议修改

| 问题 | V1 现状 | V2 处理 |
| --- | --- | --- |
| 取向 | 全自动避障排除在首期；途经点手工添加 | 规划器分三档，档 1、2 进首期，档 3 二期；途经点改为可选提示 |
| 点位权威来源 | §3 说关节目标唯一权威，§1.1 又说拖动工具位姿时位姿为准，切换时规则缺失 | 引入 `teachType`，一个点只有一个权威（第 3.1 节） |
| 求解器与朝向 | 承诺"工具朝向 + 绕接近方向转角"，但文中说内置求解器主要算 J1/J2/J3/J5 | 引入能力矩阵，声明可约束的朝向自由度（第 3.2 节） |
| 隔板验收 | 当前合同要求隔板数不少于层数，验收却写"无隔板、7 张、8 张均按已支持合同" | 先扩展合同，再开放验收项（第 5 节） |
| Pick 参数不生效 | 要修，但又不能静默改变已发布流程 | 冻结旧复合动作，新能力走显式运动段（第 3.5 节） |
| 里程碑编号 | W0–W5、A–D、G1–G4 三套并行 | 合并为 M0–M5，并给出对照表（第 8 节） |
| 阈值与默认值 | 容差"来自已确认配置"，没说谁确认、默认多少 | 给出占位初值表，随机型标定（第 4.5 节） |
| 外部依赖 | W0 依赖 03 文档和"通用编辑保护规划" | 列入依赖表，M0 内保底实现最小草稿保存（第 10 节） |

## 2. 设计取向：意图优先，引擎规划，示教降为覆盖

### 2.1 分层模型

```text
L0 语义任务    从哪个料位抓、放到哪个位置、用哪个工具、夹具默认接近方向、净空/速度偏好
   ↓
L1 目标位姿    预设点 / 工作点 → 相对参考对象的工具位姿目标；预取、抬升、预放、回撤由模板派生
   ↓
L2 运动规划    按段选择规划器：走廊（档1）/ 直线加检查（档2）/ 采样规划（档3）
   ↓
L3 时间参数化  轴速度与加速度约束 → 可执行轨迹
   ↓
L4 动作流节点  MoveTo / MovePose 显式运动段 + GripClose / Attach / Detach（同一份动作流）
```

规则：L0、L1 是用户可编辑的数据；L2、L3 的输出是**派生缓存**；L4 是现有动作流节点，仍是唯一可执行内容。

### 2.2 用户与引擎的分工（V2）

| 事项 | V1 | V2 |
| --- | --- | --- |
| 抓放位置 | 用户教点或选预设点 | 不变，预设点仍是默认入口 |
| 接近/抬升/回撤点 | 用户设距离，系统生成候选 | 同 V1，但默认值来自模板，可整体沿用 |
| 搬运途中怎么走 | 用户手工加途经姿态 | **引擎生成**；用户只在规划失败或有工艺要求时加"途经提示" |
| 避障 | 排除在首期之外，仅检查 | 档 3 提供自动避障，档 2 提供检查加有界重试 |
| 示教 | 主流程 | 覆盖手段：改某一段、锁定某个中间姿态、指定 IK 分支 |

### 2.3 V2 操作流程

1. 选机器人和工具，点"配置取放"。
2. 选来源和目标（预设点或三维点选），夹具朝向取默认或在高级区调整。
3. 点"生成轨迹"：引擎按档位生成各段，并显示每段的检查状态。
4. 逐段预览；某段失败时，面板给出失败段、原因和首个冲突对象，提供"调整目标 / 加途经提示 / 提高净空 / 换 IK 分支"。
5. 保存。保存的是任务（L0、L1）和生成的动作流节点，规划结果作为带摘要的缓存一起保存。

途经提示的语义：规划器必须经过该姿态，其余部分仍自动生成；删除提示后恢复全自动。提示本身存进工艺卡元数据，并编译成 `MovePose` 节点，不另建存储。

## 3. 共享基础补缺

### 3.1 点位权威来源：`teachType`

每个点只有一个权威来源，转换必须显式。

| teachType | 权威数据 | 派生数据 | 典型用途 |
| --- | --- | --- | --- |
| `toolTarget` | 相对参考对象的工具位姿（位置 + 朝向 + 单位 + 旋转顺序） | 关节解（含分支提示），由求解器给出 | 取放目标、预取点等语义点 |
| `jointTarget` | `Pose` 的轴目标 | 工具位姿，由正向运动学给出，只用于核对 | 待机位、不支持 IK 的模型 |

规则：

- 调轴记录姿态，默认生成 `jointTarget`；在支持 IK 的模型上可选择"转为工具目标"，转换时显示误差并让用户确认。
- 对 `toolTarget` 的点，关节控件变为"分支选择"（肘上/肘下等）；直接改关节值会触发"转为关节目标"的确认，不静默改类型。
- 数值输入只作用于 `toolTarget`；对 `jointTarget` 输入 XYZ，要求先转换。
- 保存的点记录 `teachType`，重开后含义不变。

### 3.2 求解器能力矩阵

用两个维度描述一台机器人，规划档位按这两个维度开放。

**运动学能力**

| 等级 | 含义 | 可用操作 |
| --- | --- | --- |
| C0 | 只有外观网格 | 摆放、展示、标记待配置点 |
| C1 | 有关节/轴定义 | 调轴、记录姿态、轴运动预览 |
| C2 | 有 IK，能约束部分朝向自由度 | 工具目标拖动、可达性检查；声明可约束的自由度 |
| C3 | 有完整 6D 位姿 IK | 任意位姿目标 |

**碰撞几何**

| 等级 | 含义 |
| --- | --- |
| K0 | 未配置碰撞体 |
| K1 | 使用默认简化碰撞体 |
| K2 | 声明了精度范围的碰撞体 |

**档位门槛**

| 规划档 | 运动学 | 碰撞几何 | 结果标注 |
| --- | --- | --- | --- |
| 档 1 走廊 | 桁架 C1，机械臂 C2 | K0 可用 | K0 时标"几何预览，未检查碰撞" |
| 档 2 直线加检查 | C2 以上 | K1 以上才可标"碰撞已检查" | K0 时只给几何预览 |
| 档 3 采样规划 | C2 以上 | K1 以上，必须 | K0 时不开放 |

**待核实**：V1 说内置求解器主要算 J1/J2/J3/J5。需要确认它能约束哪些朝向自由度。如果只能约束其中一部分，就在机型能力定义里声明（例如"仅绕竖直轴转角可约束"），并在界面隐藏它无法满足的朝向选项，而不是让用户配出无解的点。

### 3.3 碰撞体的默认与分级

- 为料架、立柱、托盘、定位座、常见夹具提供**默认碰撞体**（盒、胶囊或凸包），随组件模板版本化。否则每个场景都要手工补，准备成本会压垮自动规划的收益。
- 碰撞体与显示网格分开保存，记录精度范围，并在三维中可视化，允许人工微调。
- 工件挂接后加入机器人移动碰撞集合，放下后回到环境集合（V1 已有）。
- 预期接触只豁免指定对象对和指定阶段（V1 已有），不关闭整段检查。
- 相邻链接的正常重叠按关节拓扑排除，其他自碰撞保留。

### 3.4 数据合同草案

字段名为示意，落地时需与现有 `contracts/index.ts` 对齐，并走版本化合同。

### 3.5 旧 Pick/Place 的处理策略

V1 要求修正 Pick 接近偏移未被消费、抬升偏移没有表单入口的问题，同时又要求不能静默改变已发布流程。建议：

1. **冻结**旧 Pick/Place 复合动作的运行语义，不改动。
2. 旧节点的表单上，对不生效的字段标注"未生效"或置灰，避免误导。
3. 新向导一律生成显式运动段加交接动作（V1 §2 已有这个方向）。
4. 提供**可选迁移**："将旧取放升级为显式轨迹"，升级前显示前后运动差异。
5. 回归测试锁定旧行为，新增测试覆盖迁移。

## 4. 规划器设计

### 4.1 三个规划器与统一接口

```ts
interface MotionPlanner {
  id: 'corridor' | 'linear' | 'sampled';
  supports(cap: RobotCapability, geom: CollisionGrade): boolean;
  plan(req: SegmentRequest): PlanResult;   // 纯函数，同输入同输出
}
```

| 规划器 | 做什么 | 用于 |
| --- | --- | --- |
| `corridor` | 抬到净空高度 → 平移或转座 → 下降；净空随垛顶和障碍重算 | 桁架整段；机械臂自由空间段的档 1 版本 |
| `linear` | 沿给定方向的工具直线，逐步求关节解，校验限位、分支连续性和碰撞 | 接近、抬升、预放、回撤 |
| `sampled` | 关节空间 RRT-Connect，加路径缩短，再时间参数化 | 机械臂搬运和回程中的自由空间段 |

桁架与机械臂共用同一接口、同一摘要和缓存机制，区别只在轴能力声明和所选规划器。

### 4.2 各段默认规划器与失败回退

| 段 | 档 1 | 档 2 | 档 3 |
| --- | --- | --- | --- |
| 待机 → 预取 | 走廊 | 走廊 | 采样 |
| 预取 → 取料 | 直线 | 直线加检查 | 直线加检查 |
| 取料 → 抬升 | 直线 | 直线加检查 | 直线加检查 |
| 抬升 → 预放（带料） | 走廊 | 走廊加检查 | 采样（带料碰撞集合） |
| 预放 → 放料 | 直线 | 直线加检查 | 直线加检查 |
| 放料 → 回撤 | 直线 | 直线加检查 | 直线加检查 |
| 回撤 → 待机（空载） | 走廊 | 走廊加检查 | 采样（空载碰撞集合） |

**接触前后的接近和退出段始终是直线，任何档位都不由采样规划生成。**

失败回退阶梯（有界，逐级尝试）：

1. 同一目标换备选 IK 分支。
2. 提高净空或延长接近距离后重试（次数和上限由配置给定）。
3. 档 3 启用时，对**自由空间段**改用采样规划连接。
4. 仍失败：返回失败段、原因（不可达关节 / 首个碰撞对象 / 关节跳变位置），保留草稿。

任何一级都**不降级为未经检查的关节插补**。这条沿用 V1 §4 的原则。

### 4.3 确定性与缓存

- 摘要 `digest` 覆盖：机型与求解器版本、工具变换、范围内物体的变换与碰撞体版本、物料尺寸、起始姿态、任务参数、规划器版本、种子。
- 采样规划固定种子；同输入摘要回放同一条路径。
- 编辑与预览模式下，摘要变化自动重规划，旧结果标记 `stale`。
- **已发布流程**：摘要不匹配时默认**阻止运行并给出原因**，除非该流程显式勾选"允许运行时重规划"（默认关）。原因：自动重规划会让同一份已发布流程在不同时间走出不同路径，破坏可复现性。该策略见第 12 节待确认问题。
- 缓存随发布快照保存、往返一致。

### 4.4 运行位置

- 规划核心写成纯 TypeScript 模块，在 Web Worker 中运行；拖动产生新请求时取消旧请求，并用代数编号丢弃过期结果（V1 已有此规则）。
- 预览和仿真播放使用同一份运动求值，防止预览一条线、播放另一条线（V1 已有）。
- 服务端检查器与编译器只校验**结构、能力版本和摘要格式**，不重新规划，避免出现 TS、C# 两套规划实现而语义分叉。代价是服务端无法独立证明路径无碰撞，需要在验收说明里写明"碰撞结论来自编辑器规划"。

### 4.5 参数初值（占位，需按机型实测标定）

| 参数 | 占位初值 | 说明 |
| --- | --- | --- |
| 直线段采样步长 | min(最小碰撞体半尺寸 ÷ 2, 10 mm) | 保存并显示在检查覆盖说明里 |
| 直线偏差容差 | 1 mm | 随机型能力定义保存 |
| 朝向偏差容差 | 1° | 同上 |
| 净空余量 | 50 mm | 可按任务覆盖 |
| 接近距离 / 抬升距离 / 回撤距离 | 100 / 250 / 150 mm | 沿用 V1 §3.1 示例值，仅作占位 |
| 规划预算 | 交互预览 2 s，最终确认 10 s | 超时返回失败并带当前最优诊断 |
| 采样规划迭代上限 | 5000 次，换种子重试 3 次 | 首个机型实测后调整 |
| 路径缩短迭代 | 100 次 | 同上 |

## 5. 桁架码垛的修订点

V1 §9 的方向正确，复用 `stackPattern`、工具平移轴映射和现有交接逻辑也合理。需要调整四处：

1. **用 `corridor` 规划器表达 §9.5 的阶段**：升降段锁水平目标，水平段保持升降位置。净空高度 = max(当前垛顶含隔板, 走廊内障碍顶) + 夹具与工件下沿到 TCP 的距离 + 余量，每层、每批重算。桁架不需要档 3。
2. **隔板策略先扩展合同再开放**：新增 `separatorPolicy`（`none` / `interlayer` / `interlayer+top`），同步更新配方、目标高度、完成条件和前后端合同。在此之前，验收表中"无隔板""仅层间 7 张"两项标为"待合同扩展"，只有"含顶层 8 张"对应当前合同。
3. **入口清点表放进 M0**：`GantryPoseResolver` 和 `GantryStackController` 属于程序化场景或其它运行入口。实施前列出每个入口驱动哪些轴、物料和托盘，保证同一时刻只有一个有效运动所有者。
4. **双工具互锁用同一套碰撞检查**：两工具及其所持物料之间的避让，复用第 3.3 节的碰撞集合，而不是另写一套互锁几何。

## 6. 不变量清单

把 V1 中散落的"不能……"收敛成一份清单，设计、实现和验收都引用编号。

| 编号 | 不变量 |
| --- | --- |
| INV-1 | 可执行内容只有一份：动作流节点；专用视图只是它的编辑视图 |
| INV-2 | 每个点只有一个权威来源（`teachType`），派生数据只作核对 |
| INV-3 | 规划结果是派生缓存，绑定输入摘要，不是编辑真相源 |
| INV-4 | 预览与运行使用同一份运动求值 |
| INV-5 | 任何失败不降级为未经检查的运动；失败保留草稿和具体原因 |
| INV-6 | 验证状态分项（配置/可解/碰撞/交接），每项有未检查、通过、失败、已过期 |
| INV-7 | 仿真、监视、真实执行相互隔离；浏览器计算不直接下发真机 |
| INV-8 | 旧版本语义不变；新语义版本化，不支持时明确拒绝，不忽略字段 |
| INV-9 | 库存和交接真实：不瞬移、不凭空补料、未夹紧不挂接、未接触不放料 |
| INV-10 | 引用稳定：克隆或复制不按名称或数组顺序绑定另一台机器人的关节、工具、料位 |

## 11. 最小可行第一刀

目标：证明"零示教"成立，范围尽量小。

- 机型：只做内置机械臂（先确认它能约束的朝向自由度）和一个桁架场景。
- 输入：上料台、下料台各一个预设点，一个工具，一个工件。
- 能力：档 1 的走廊加档 2 的直线接近/退出；默认碰撞体只覆盖料台和一根立柱。
- 产物：工艺卡、四项检查状态、逐段预览、保存重开。
- 不做：采样规划、时间参数化、真机、尾批、其它轴布局。
- 验收：不加途经点生成完整取放；把立柱移到路径中间后，报告中段失败并指出冲突对象；摘要变化使旧结果标记过期。

这一刀跑通后，再决定档 3 的投入。
