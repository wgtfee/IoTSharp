## 1. 判断与范围

当前编排的主要负担是：用户需要自行把设备、工作点、物料槽、工具、执行轴、信号和动作节点关联起来；编辑器提供了这些能力，却仍把不少关联工作交给用户。

建议以“选中设备或工位，完成一个工艺任务”为常用入口。专业流程图继续表达跨设备协作和复杂分支；常用任务通过参数面板生成、检查和修改同一份 Action Flow V2。沿用现有 SceneManifest、RouteGraph、校验器、运行器和版本机制。

本轮主范围：`/iot/digital-twin/workbench`，以及它使用的 ThreeJsEditorHost、ComponentPropertyPanel、ActionFlowDesigner、节点属性、模板和绑定逻辑。场景中心、3D Viewer 与 2D 编辑器列为共享合同回归对象。组件设计器只检查入口衔接，不在本轮重做几何建模工具。

### 当前界面与设计依据

- 工作台采用深色工程画布、左右属性面板、Element Plus 表单；现有 3D / 流程 / 分屏和专业编辑 / 运行预览是两组不同概念。
- 路由入口：`ClientApp/src/router/route.ts:100`；工作台负责整体状态，ThreeJsEditorHost 负责画布，ActionFlowDesigner 负责动作图。
- `AGENTS.md` 要求增量升级，保留 Product / Device / Asset 分工，不将新能力混入规则链或重写整个平台。
- 组件目录 README 说明现有参数化资源与场景实例机制；实际消费路径已由工作台与组件 Host 的 imports 确认。
- 三份 3D 设计方案是规划依据，其中动作流方案明确标为“实施基线草案”。不能把它们描述的未来能力当作当前实现，也不能直接把其中旧问题清单当作今日缺陷。
- 明确例外：未发现针对本轮交互问题的已批准例外。已有三维安全节点约束是需保留的运行规则。

## 5. 目标操作路径

### 普通工位：加工、检测、套袋

1. 选中工位，点击“配置工艺”。
2. 选择“加工完成后放行”，确认到位批次、加工时间、完成阶段。
3. 系统生成已绑定本工位的流程；显示可读摘要，例如“到位 → 加工 5 秒 → 标记已套袋 → 放行”。
4. 点击“试运行”，查看当前等待原因；需要特殊分支时展开流程图。

拟定验收目标：标准工位无须手填 ID、节点路径或 JSON；基础配置在同一工位上下文内完成。

### 机器人取放 / 桁架码垛

1. 选中执行设备，选择“取放”或“码垛”。
2. 选择来源、目标、工具和批量，缺少工作点时原位记录或创建。
3. 确认取放目标、工具方向与允许的运动约束，由引擎生成轨迹；示教和必经点用于修正。桁架配置来源/托盘基准、实际轴能力、行列层、批量、隔板与换托，按批次自动求值。
4. 预览实际运动路径和物料交接；桁架另需逐层及整托检查。新轨迹通过同一动作流的版本化节点实际执行，区分几何预览、可运行仿真与真实信号联调。详见 [05 机器人取放与桁架码垛自动规划 V2](05-机器人取放与桁架码垛自动规划V2.md)。

拟定验收目标：参数只填写一次；多个动作节点引用同一组已确认的资源。未匹配的设备或工作点明确保留“待配置”，不猜测填入其它设备。

### 接入实时点位

选工位 → 打开“信号” → 一张表配置 Ready / Busy / Done / Fault 或轴反馈 → 查看最新值及换算结果。修改 Key 保留 bindingId 和现有关联。

## 6. 工作区结构

保留当前工程视觉风格和画布。将功能按任务呈现，避免再叠加一组永久工具栏。

```text
场景名称 | 未保存 / 已保存 / 保存失败 | 保存 | 模拟 | 发布检查
┌────────────┬────────────────────────┬──────────────────┐
│ 搭建       │                        │ 当前设备/路线/节点 │
│ 工艺       │    3D / 流程 / 分屏     │ 基础参数           │
│ 信号       │    作为布局选择         │ 本任务需要的配置    │
│ 检查       │                        │ 高级配置按需展开    │
└────────────┴────────────────────────┴──────────────────┘
底部按需打开：诊断 | 模拟状态 | 等待原因
```

- 任务区允许自由切换，不强制按步骤完成整条产线。
- 模拟 / 实时监视 / 真实命令执行具有不同含义；布局切换不会改变运行语义。
- 用户可展开高级图和字段。已自定义的图不能被简易参数面板静默重新生成。
- 中文业务名称优先：执行设备、工作点、物料位、工具坐标、执行轴；技术标识放入高级详情。

## 8. 验收方法

以同一组真实任务记录前后步骤、跨面板切换、手工标识输入、错误恢复次数和完成结果，避免用控件数量代替效率。

- 空白创建、无路线静态布局、未连完的动作、未选设备的节点均能保留编辑成果；未完成内容不能直接发布或启动不满足条件的运行。
- 第二条路线的属性和测试作用于第二条路线。
- 改设备点位 Key 后，工位信号、动作条件和次路线引用仍正确。
- 删除带 TCP / 槽位 / 动作的设备可查看影响、撤销和保存重开。
- 标准工位模板无手填 ID/JSON；高级修改不被简易面板覆盖。
- 区分仿真、实时监视与真实命令执行，不自动切换到设备控制。
- 浏览器验证包含 1366×768 与 1920×1080、侧栏开关、空状态、长名称、多路线和至少两个设备的候选列表。分屏可折叠或切页，不以固定最小宽度挤掉编辑区域。
- 代码实施后执行完整 `npm run typecheck`、`npm run build` 及受影响的专项测试；数据库、浏览器、PLC 联调分别记录，不互相替代。
