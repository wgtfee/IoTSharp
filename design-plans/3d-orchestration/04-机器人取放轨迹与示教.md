# 机器人取放与桁架码垛编排完整方案 V1

日期：2026-11-05。核查基线：`Develop / 4d3b7feb`。状态：待实施设计；本轮只核查源码并补充规划，没有修改运动程序、运行浏览器或连接真实机器人。

适用场景：IoTSharp 三维工作台中的机器人取放、固定工位上下料与桁架码垛。完整方案包含两个验收场景：机器人固定取放，以及桁架按托盘配方码垛、隔板交接和满托换托。共同编辑与运行能力复用，设备运动方式分别声明。

目标操作：**选机器人与夹具 → 选取放位置 → 确认姿态 → 配接近/退出 → 加途经点 → 检查预览 → 保存工艺**。普通使用者不输入对象 ID、节点路径或 JSON；模型准备者负责一次性的轴、工具和预设点配置。

桁架操作：**选桁架与工具 → 教取料位和托盘基准 → 填行列层/批量 → 配搬运高度及隔板 → 预览整托 → 保存工艺**。用户设置基准与规则，引擎计算每次目标；不要求逐个填写整托坐标。

本方案描述完整目标与分期交付，不代表这些能力已全部存在，也不以本方案批准真实机器人运动。沿用现有场景、动作流与设备边界，不引入第二套运行引擎。

- Audited surface：`/iot/digital-twin/workbench` 内机器人取放工艺及其三维、属性、动作图入口。

## Design decision

用户先教关键点，再调整各段运动方式，系统显示实际求解出来的路径。常用入口是一张“取放工艺卡”，内部展开已有动作图。用户不用为了每个接近、夹紧、抬升动作重复选机器人、工具和物料槽。

关键点决定“到哪里、夹具朝哪里”，运动段决定“怎样过去”。取放轨迹独立于输送线的 RouteGraph；后者仍负责物料运输与路线分流，不能直接当作机械臂运动路径。

### 用户与引擎的分工

| 事项 | 用户/模型准备者提供 | 引擎负责 |
| --- | --- | --- |
| 抓哪里、放哪里 | 工艺目标、物料位、抓取面、允许放置的支撑位置 | 高亮候选、计算点击坐标、维护对象引用 |
| 夹具怎么朝向 | 抓取方向及绕该方向的转角，或已示教姿态 | 显示工具坐标，计算候选轴姿态与误差 |
| 怎样走 | 运动类型、接近/退出距离、途经姿态 | 生成派生点、求解与检查连续运动段 |
| 是否可以交接 | 物料规格、容量、接触约束、信号映射 | 检查库存、夹紧、接触、许可及失败原因 |
| 真实设备如何运行 | 已适配机型、标定、控制器程序及现场验证 | 通过设备适配发任务、接收结果和遥测 |

引擎不能只凭外观模型确定可靠抓取点，也不能把表面法线、物体中心或名称相似当作已确认的工艺语义。

## Reuse

- 复用 captureActuatorPose 记录仿真轴或已采集的真实反馈，不新建一套姿态存储。
- 复用 WorkPoint 的对象局部位置、MaterialSlot 的库存和动态堆叠、ToolFrame 的工具关系、Pose 的轴目标。
- 复用 MovePose、MoveTo、GripClose、Attach、Detach 及联锁、超时和故障语义；保留现有 Pick/Place 的兼容路径。
- 复用动作图的同一份节点与边、稳定 ID、草稿发布与校验机制；轨迹面板是这些节点的专用编辑视图。
- 桁架复用 stackPattern、工具平移轴映射与现有交接逻辑；图纸中的两工具、隔板和满托流程仅作为行为参考，去除固定 ID 与布局参数后再生成通用模板。
- 拟新增的轨迹段编辑和路径预览组件只负责当前工艺上下文，不新建调度器或接入第二套规则链。

## Changes

### 0. 组件准备：复杂配置只做一次

模型准备者为可运动机器人补齐：关节层级、旋转/平移轴、零位、单位、限位、基座、法兰、可用求解器及版本；为夹具补齐 TCP、工具朝向、夹紧轴、物料兼容范围及碰撞几何。关键数据缺失时保留展示能力，不开放未支持的轨迹功能。

为料架、定位座、托盘等组件提供有业务名称的预设点，例如“上料抓取位”“托盘落料位”。预设点保存相对组件的位置、朝向和用途，在实例化时生成稳定的场景工作点引用。组件模板更新不能静默改写已有场景实例。

| 模型能力 | 可用操作 |
| --- | --- |
| 只有外观网格 | 摆放和展示；可标记待配置工作点，不能宣称机器人能运动 |
| 有关节和轴定义 | 调轴、记录关节姿态、按已实现的轴运动预览 |
| 有适配的正/逆向运动学 | 工具目标拖动、候选姿态求解、可达性检查 |
| 有经验证的连续插补与碰撞能力 | 对支持的段进行直线和碰撞检查，并报告检查范围 |

机器人模型和现场设备通过现有场景绑定关联；Product 仍是能力模板，Device 仍是实际数据/命令端点，业务设备归属沿用 Asset。模型资源不是 Device，不把空间点位混入设备遥测 Key。

运动模型采用明确尺寸和比例。非均匀缩放、负缩放或单位不明的机器人先归一化并重新校验；不能拖大模型后继续沿用旧臂长与已通过的路径结果。

### 1. 用户操作：选设备 → 教点 → 调整路线 → 预览

1. 选机器人，点击“配置取放”。带入机器人和兼容工具，选择来源、目标物料位。
2. 点击“示教取料点”：通过仿真关节控件摆好姿态，或在支持的模型上拖动工具目标，再点“记录”。同时显示夹具朝向；不能只记一个 XYZ。
3. 同样记录放料点。相对来源、目标对象保存工作点；界面可显示世界坐标供观察，不能把世界坐标直接写进现有局部坐标合同。
4. 设置接近方向、距离和离开距离，生成预取、抬升、预放、回撤的候选点。候选点必须通过当前机器人能力检查；不能仅凭偏移数值标为可达。
5. 搬运途中需要绕开立柱或设备时，点击轨迹“添加途经姿态”，调整机器人并记录；可插入、排序、删除，实时看到改变后的路径。
6. 逐段或完整预览，检查工具姿态、物料交接与失败位置，保存为当前机器人的取放工艺。改变工具或场景布局后重新验证。

基础表单只显示来源、目标、工具、取放姿态、接近/离开距离和速度；途经点按需添加。数值、坐标系、轴目标和插补细节在高级区展开。

### 1.1 位置的四种设置入口

| 入口 | 用户怎么操作 | 保存规则 |
| --- | --- | --- |
| 选预设点，默认推荐 | 从来源/目标组件选择“抓取位”“放料位” | 引用稳定工作点，可显示相对偏移；保留原模板与实例关系 |
| 在三维中点选 | 进入选点模式，点击允许的物料或定位面，拖箭头微调 | 点击先生成候选，再转为选定参考对象的局部坐标；确认后保存 |
| 调轴记录姿态 | 仿真中调各关节，或读取可用的设备反馈，点击记录 | 关节目标为主；保存当前工具、模型版本、反馈来源/时间及可核对的工具位姿 |
| 精确数值 | 输入位置和角度，明确相对哪个对象 | 默认显示毫米/度，按当前合同转换存储；不让显示单位改变轴定义含义 |

选点模式只接受当前任务允许的来源/目标对象；遮挡时可隔离目标、切视角或从对象树选择。显示候选名称、接触位置、方向和参考对象；Esc 取消，不污染已保存点位。没有命中目标时不使用地面或世界原点兜底。

点击表面只能获得位置和候选法线；还需要用户确认夹具朝向及绕接近方向的转角。对圆柱、孔洞、对称工件等不能仅以包围盒中心作为有效抓取位。源物料的工艺抓取面和目标支撑面分别建模，工具 TCP 与工件中心不能混用。

拖动操作驱动“目标工具位姿”，再由支持的求解器预览机器人姿态；不允许把末端网格单独拉离机械臂。无解时保留红色/图标错误候选与文字原因，当前有效机器人姿态不跳变。用户仍可保存该候选为待配置草稿。

同一目标存在多组关节解时，优先延续当前关节分支，并允许在高级区预览其它解。记录的是明确选定的解或分支提示；不能每次预览随机换肘部方向。真实反馈超时、轴不全或工具不一致时，不把旧值当作当前姿态记录。

### 1.2 工作台布局与编辑状态

保持现有三维工作台，在“工艺 → 机器人取放”中进入专用视图。下图是建议线框，控件沿用现有组件样式。

```text
机器人 A / 取放工艺      草稿状态      保存草稿  检查  仿真预览
┌────────────────┬────────────────────────┬──────────────────┐
│ 设备与工具     │                        │ 当前点/运动段    │
│ 取料位置       │  三维机器人、目标标记  │ 相对：上料台     │
│ 放料位置       │  方向箭头、实际路径    │ 位置 / 工具朝向  │
│ 搬运与回程     │                        │ 接近 / 退出距离  │
│ 条件与确认     │  点击点位可定位属性    │ 运动方式 / 速度  │
└────────────────┴────────────────────────┴──────────────────┘
阶段条：预取 → 接触 → 夹紧 → 抬升 → 搬运 → 放料 → 回撤
底部按需打开：检查结果、当前等待原因、逐段播放、动作图
```

- 左侧步骤可自由切换，显示“待配置 / 已配置 / 需重查”，不把填写完整等同于运动验证通过。
- 点位可直接在三维或阶段条选中；右侧字段同步，不因切换三维/流程布局重置配置。
- 常用界面不显示技术 ID；错误提示示例：“第 3 段无法到达：已超出肘关节行程”，提供“定位目标 / 调整姿态”。
- 检查状态同时使用文字和图标，不只依靠颜色。窄窗口允许属性抽屉和底部面板折叠，保留三维操作面积。
- 一次拖动只产生一个撤销步骤；取消示教恢复原值。切设备、离开场景时沿用通用草稿保护，未完成也可保存。
- 本视图“逐段预览”是新增的隔离仿真任务，必须显式提供起始姿态、物料和信号夹具；不是声称现有工作台已经具备单机器人隔离运行。

### 2. 标准轨迹及动作顺序

| 阶段 | 目标与动作 | 运动要求 |
| --- | --- | --- |
| 待机 → 预取 | 从已知起始姿态到取料接近点 | 可选择经验证的关节运动；入口也必须检查，不允许从任意姿态突然切到已教点。 |
| 预取 → 取料 | 工具沿已配置方向接近抓取位置 | 需要直线接近的工艺必须使用已实现并验证的工具直线插补；保持指定工具朝向。 |
| 取料交接 | 到位、夹紧、确认、挂接物料 | 复用库存、工具占用、接触和夹紧校验。不得提前把物料挂到夹具上。 |
| 取料 → 抬升 | 带料离开来源 | 按工艺方向退出；检查整个工件离开料架，距离不能只考虑 TCP。 |
| 抬升 → 途经姿态 → 预放 | 带料搬运 | 途经点可有多个；检查机械臂、夹具和物料的运动范围，不能只画 TCP 连线。 |
| 预放 → 放料 | 到目标支撑位置 | 有直线要求时按工具直线段执行；放置姿态属于目标的一部分。 |
| 放料交接 | 确认接触与容量，释放、松爪 | 沿用 Detach/Place 的交接规则，不用空中 GripOpen 绕过释放约束。 |
| 放料 → 回撤 → 待机或下一轮 | 工具退出目标区域后回程 | 回程独立检查；空载回程与带料去程不能默认共用未经验证的路线。 |

新向导生成的精细取放优先使用显式运动段和交接动作。例如：MoveTo 接触 → GripClose → Attach → MoveTo 离开。放料使用已到接触位置的 Detach，再执行回撤。避免显式轨迹与 Pick/Place 内部隐含运动重复执行。现有复合动作仍兼容，不能静默改变已发布流程的运动。

### 3. 点位、姿态、坐标系必须一致

- **关节目标**：以 Pose 的轴目标为准，工具位姿由正向运动学计算；不能同时维护一份可能矛盾的 XYZ 当作第二个目标。
- **工具位姿目标**：以相对参考对象的位置与朝向为准，关节姿态作为求解分支提示和验证结果。相同位置可能对应不同机械臂姿态，要保留当前姿态连续性。
- 界面明确“相对取料台 / 放料台 / 机器人基座 / 工具”；偏移方向通过相应坐标变换求得，不能统一解释为世界 Y 轴抬高。
- 当前 resolveWorkPointWorld 的不同动态槽位分支对偏移存在不同计算路径；实施前补齐旋转来源、旋转托盘、工具方向的合同与回归案例，保留旧版本解释。
- 位移与角度显示单位明确，内部单位换算复用现有执行轴定义。接近距离、速度和容差不能依赖任意默认值掩盖缺失配置。
- 工作台移动后，相对工作点随其变换；机器人固定关节 Pose 不会自动跟随台面移动。二者相关的段必须标记待重算，重新检查可达性与路径。
- 码垛根据行、列、层和物料尺寸计算当前放置目标，再应用接近/回撤规则；无须每层手教所有点。每批固定所使用的目标快照并检查目标仍有效。
- 首批动态来源按“停稳、到位、许可、取放”处理。运动输送带跟踪需要时间同步、目标跟踪和对应控制能力，单独规划。

### 3.1 坐标计算示例

以下仅演示位置生成规则，不是通用推荐距离，也未在当前机器人上验算。假定来源和目标各自局部 Y 轴朝上，抓取/放置工作点已正确标定为所需 TCP 目标，工具朝下。

| 点 | 相对对象 | 局部 XYZ，毫米 | 来源 |
| --- | --- | --- | --- |
| 取料点 | 上料台 | `[0, 120, 0]` | 用户选点并校准 |
| 预取点 | 上料台 | `[0, 220, 0]` | 取料点沿离开方向增加 100 |
| 取后抬升点 | 上料台 | `[0, 370, 0]` | 取料点沿离开方向增加 250 |
| 放料点 | 下料台 | `[200, 80, 150]` | 用户选点并校准 |
| 预放/回撤点 | 下料台 | `[200, 230, 150]` | 放料点沿离开方向增加 150 |

来源与目标各有参考坐标，不能把表中的数值直接当作一条世界坐标路径。上料台转动时，依附其上的点和方向一起变换，再重新求解机器人姿态。预取与回撤距离可分别设定，不强制对称。

内部统一经过：参考对象变换 → 目标工具位姿 → 扣除法兰到 TCP 的工具变换 → 关节求解。若选的是工件特征位，还要应用经过确认的抓取偏移。仅加减工具长度不能替代带旋转的完整坐标变换。

现有 WorkPoint 的 objectId、nodePath 与各动态槽位分支必须在合同中明确唯一参考语义。新界面显示实际使用的参考节点；旧数据不自动改解释。旋转插补内部使用无欧拉角跳变的表示，编辑器与现有 localRotation 之间通过明确的旋转顺序转换。

### 4. 运动段：区分关节运动和工具直线

**关节运动**用于到达指定轴姿态，工具经过的曲线由各轴运动决定。现有 MovePose 可以作为起点，但当前实现不能直接等同于真实控制器 MoveJ 的同步、速度和加速度语义。

**工具直线**用于需要按固定方向接近或退出的段。应在位置及朝向之间生成连续目标，逐步求关节解，校验限位、分支连续性和整段可达性；还需约束各轴速度与加速度。有任一处无有效解时返回具体段与位置，不退化为关节运动继续运行。

实施采用版本化的运动段参数扩展现有 MoveTo/MovePose 消费路径，前端、服务端检查器、编译器与支持该语义的运行器共同支持后才开放相应选项。旧版本保持原运动含义；不支持的新语义必须明确拒绝，不能忽略字段后声称已直线执行。

首版各段端点停止，取放接触点不得随意做圆角过渡。平滑过渡、圆弧和连续多段运动在时间参数化和碰撞验证具备后再增加。画一条平滑曲线不等于机器人能够沿它运动。

速度分开表达：关节运动使用各轴速度/加速度约束，工具直线使用工具速度/加速度并同时检查轴约束；当前 speedRatio 只作为倍率，不能直接标成 mm/s。未定义加速度能力的旧路径不能显示为已验证时间曲线。

这一区分参考 [Universal Robots 官方 Move 文档](https://www.universal-robots.com/manuals/EN/HTML/SW5_20/Content/prod-usr-man/complianceUR30/SW_sections/first_program/move.htm)：关节空间运动与工具直线运动具有不同路径和速度参数。本项目的同名或近似动作尚不能等同于该厂商控制器指令。

### 4.1 计算流程和运行一致性

```mermaid
flowchart LR
    A[已确认的工作点与工具] --> B[参考坐标换算]
    B --> C[点位求解与分段插补]
    C --> D[关节连续性和运动约束]
    D --> E[全段碰撞与交接检查]
    E --> F[带版本的仿真预览]
```

重计算以机器人、工具、场景、物料和流程版本为输入。耗时计算可在独立工作线程执行；拖动产生新请求后取消或丢弃旧请求结果，防止旧路径覆盖新配置。最终确认时对最新输入完成检查，不能把拖动中的降采样预览标成最终验证。

路径规划结果必须绑定起始姿态。进入运行时若起始姿态、工件状态或目标变换不同，重新求解并验证，不能沿用旧缓存。用同一运动求值逻辑驱动路径显示与仿真播放，防止“预览走一条线，实际播放走另一条线”。

直线插补遇到部分可达时，允许显示到失败点的诊断轨迹，但整个段保持失败，不能把前半段当作完整成功。连续性、碰撞与几何路径是不同检查项；可参考 [MoveIt 官方 Cartesian Path API](https://moveit.picknik.ai/humble/api/html/classmoveit_1_1planning__interface_1_1MoveGroupInterface.html) 中的步长、关节跳变和碰撞检查边界。本轮不因此引入 ROS 或 MoveIt 运行依赖。

### 5. 路径预览必须来自实际运动结果

- 显示实际运行器生成的工具轨迹、关键姿态和当前夹持状态；无法求解的连接可显示虚线建议，并明确为未求解。
- 选中某一段，只调整该段的目标、运动方式和速度；故障直接定位到对应字段。
- 提供分段播放、暂停与进度预览。拖动预览进度应重建独立仿真状态，不能修改真实库存或发出设备命令。
- 显示可达性、轴限位、工具姿态偏差及夹持结果；碰撞检查须覆盖自碰撞、环境、夹具和工件。
- 未配置碰撞体时明确“未完成碰撞检查”；采样检查要声明分辨率与覆盖限制，不能把两个无碰撞端点视作整段通过。
- 抓取/放置的预期接触只豁免指定对象、指定接触对和阶段；不能为避免误报而关闭整条轨迹的碰撞检查。
- 模型、工具、物料尺寸、工位位置或路径改变后使相关验证结果过期。节拍仅在运动时间模型具备时显示仿真估算，并标出夹紧等待等假设。

检查结果分别标记“配置完整”“运动可解”“碰撞检查”“交接模拟”，每项都有未检查、通过、失败或已过期状态，不用单一绿色状态替代全部含义。缺少碰撞体时只允许明确标记的几何预览，不能显示完整仿真验证通过。

障碍物范围包括料架、立柱、机台以及声明参与检查的其它设备；碰撞模型可与高精度显示网格不同，但必须记录精度范围。工件挂接后加入机器人移动碰撞集合，放下后回到环境集合。仅按明确关节拓扑排除相邻链接的正常重叠，保留其它自碰撞检查。

### 5.1 异常与恢复

| 情况 | 界面提示及处理 |
| --- | --- |
| 目标超出范围或姿态无解 | 标出目标及失败段，保留草稿；调整位置/朝向/途经姿态后重算 |
| 路径中间碰撞或关节跳变 | 标出首次检测到的位置和对象，不自动跳过或改走另一种运动 |
| 等不到物料、许可或夹紧 | 显示等待对象、条件、超时；按流程故障策略处理，不伪造完成 |
| 目标满位或未接触 | 保留持料状态，不提前松爪；返回目标容量/接触诊断 |
| 改动来源、工具或场景模型 | 相关段显示需重查；重用点位引用，不重用旧验证结论 |
| 仿真中断 | 保留诊断快照；继续前校验姿态、物料和资源状态，重置需明确重建仿真夹具 |
| 真实设备掉线或执行结果未知 | 标记状态未知，通过适配读取设备状态；不自动重发取放或自动回零 |

模拟中的暂停、重置和回撤预览不映射成真实设备控制。真实设备停止与恢复由对应控制器接口及现场规则实现。

### 6. 保存与执行仍是一套动作流

- 取放工艺卡记录模板版本、节点归属、参数映射及基线 hash；可执行内容仍是同一份 Action Flow 节点/边与其引用的 Pose/WorkPoint。
- 专用轨迹视图编辑同一组节点，并将参数、工作点、姿态和相关节点修改放入同一个可撤销事务。
- 中间态可保存草稿；不满足运行条件的轨迹保持待配置，不能用上一次成功生成的路径冒充当前内容。
- 高级图发生结构修改时进入自定义模式；不得在用户改一个距离时覆盖手工分支或途经点。
- 多个流程争用同一机器人或交接区域时保留所有权和联锁约束；轨迹可达不等于允许同时运行。

### 6.1 数据归属与版本

| 数据 | 保存归属 | 关键约束 |
| --- | --- | --- |
| 机器人能力、预设点模板 | 版本化模型能力定义，实例化到现有场景定义 | 首期支持明确模型；不靠模型名称猜关节或工具 |
| 来源、目标和容量 | 现有 MaterialSlot | 稳定引用，运行时批次/载体选择明确 |
| 工具中心与接近方向 | 现有 ToolFrame | 属于当前机器人，变更使相关验证过期 |
| 目标位置和朝向 | 现有 WorkPoint，必要时版本化扩展参考语义 | 相对引用、单位及旋转顺序明确 |
| 关节目标 | 现有 Pose / Actuator | 轴目标唯一权威；工具位姿为核对结果，不另存可冲突目标 |
| 顺序、分支、等待、交接 | 现有 Action Flow V2 | 保留一份可执行图，专用视图编辑同一节点 |
| 模板映射与派生点关系 | 版本化、可选的工艺作者元数据 | 不独立执行；重新生成先保护高级修改 |
| 路径样本与检查结果 | 版本绑定的派生结果/缓存 | 绑定输入摘要、求解器版本、初始状态和检查覆盖；不作为新的编辑真相源 |

新字段使用明确合同而非藏在未校验的任意 metadata 中。前后端检查器、保存归一化、编译和运行能力版本一起升级；未知运行语义在加载/发布时明确拒绝。旧流程保持现有执行含义，新取放模板显式声明所需能力。

删除被轨迹引用的机器人、工作点或工具时列出影响并允许撤销；克隆工艺时显示资源映射，不按名称或数组顺序把另一台机器人的关节自动绑定过来。保存重开和发布快照中，点位、姿态、节点、模板关系必须完整往返。

### 7. 仿真与真实设备的职责

轨迹面板先完成三维示教与仿真。真实设备由机器人控制器执行经过该设备验证的程序，平台通过设备适配层发任务、接收完成/故障和关节反馈。现阶段不把浏览器计算的逐帧角度直接当作真实机器人控制程序下发。

真实轨迹回显优先使用采集到的轴值和工具反馈。自动生成厂商程序、离线编程导出及控制器轨迹一致性，均需在机型、标定、工具、接口与执行验证明确后独立实施。

| 模式 | 数据来源和用途 | 运动输出 |
| --- | --- | --- |
| 三维仿真 | 独立仿真姿态、物料和可控信号 | 只驱动仿真对象 |
| 实时监视 | 已绑定设备的轴值、状态和时间戳 | 不发送运动命令；过期反馈明确显示 |
| 真实任务执行 | 已验证控制器程序、设备能力和执行许可 | 通过现有命令适配层下发任务并追踪结果 |

真实执行需额外绑定机器人基座/工位/工具的现场标定版本、程序版本和任务 ID。结果未知时先查询，使用适配层的去重与幂等机制；这些要求不能用三维播放成功替代。

### 9. 桁架码垛：位置与配方一次配置

#### 9.1 与六轴机器人共享哪些能力

共享工作点、TCP、轴单位、坐标换算、草稿/发布、仿真状态、路径检查和同一动作流。新增“桁架码垛工艺卡”，负责层、行、列、批量、隔板、托盘交接这些机器人固定取放没有的配置。

| 项目 | 六轴机器人取放 | 桁架码垛 |
| --- | --- | --- |
| 运动声明 | 关节链、工具姿态及求解器 | 实际平移轴、可选旋转轴、工具和行程 |
| 主要目标 | 取放工作点和途经姿态 | 取料基准、托盘基准、配方计算出的当前批次目标 |
| 常用路径 | 关节段或工具直线段 | 先抬升、再水平搬运、再下降、回升与回程 |
| 工艺完成 | 本次物料成功交接 | 本批交接、层完成、隔板完成、整托完成分别判断 |

不能把桁架默认写成 XYZ 三轴。业务界面显示“横移、纵移、升降、旋转”，对应具体 Actuator；当前项目场景 Y 轴向上，PLC 中命名为 Z 的升降轴仍需明确映射。

能力分三类：两轴配固定多抓位夹具，可在其可达平面做成组/整层搬运；具有足够平移自由度的桁架，可按能力做逐件或分组定位；带已声明旋转轴或变距机构的工具，才开放转向或变距。配方能生成坐标不代表设备可以摆到该坐标。

#### 9.2 用户配置的页面和字段

| 页面 | 用户填写 | 系统给出的结果 |
| --- | --- | --- |
| 设备与工具 | 桁架、物料工具、可选隔板工具；已有能力自动带入 | 支持的轴、抓位数、行程与可用码垛方式 |
| 取料位 | 来源批次、抓取基准、夹具方向、每次抓取数量 | 高亮实际来源与每个抓位对应物料，检查能否对齐 |
| 托盘基准 | 到位托盘、局部方向、第一件/第一组放置基准 | 托盘坐标轴与首批候选，不按世界坐标固定落点 |
| 码垛配方 | 行、列、层、行列中心距、首层位置、层距、放置次序、批量 | 整托轮廓、容量、编号与当前目标；不逐点手工示教 |
| 运动与隔板 | 搬运高度/净空、升降/横移速度、接近/回撤；隔板来源与策略 | 每个阶段的运动段、隔板任务和失败原因 |
| 检查与交接 | 托盘到位、许可、夹紧/真空、满托出料条件 | 逐批、逐层、整托预览及保存发布检查 |

数字框旁标明“中心距”或“净间隙”，二者不得混用。用户选择净间隙时由物料外形换算中心距，再做托盘边界与重叠检查。修改物料尺寸、行列数、层高或隔板后重新检查整托外形与行程。

三维中点击某一格可查看“第几层、第几行、第几列、由哪个抓位搬运、预计姿态”。支持切层、半透明整托、当前批次和整托范围预览。底部显示已放数量、当前层、隔板进度和托盘身份，不能只显示一个总进度条。

#### 9.3 基准怎么教，剩余位置怎么算

取料位沿用预设点、三维点选、调轴记录和精确输入四种入口。托盘先选现有定位座/StackAnchor；缺少基准时在三维确认原点、横向、纵向与上方向，再教首件或首组位置。来源、托盘、工具各自保留局部坐标和版本。

对当前合同的规则矩形阵列，假定托盘局部 Y 向上，列沿 X、行沿 Z，索引从 0 开始：

```text
物料基准位置 = [originX + 列号 × spacingX,
                firstLayerY + 层号 × layerPitch,
                originZ + 行号 × spacingZ]
```

这里计算的是已定义的物料基准位置，不必然是物料中心，更不是夹具 TCP。实际工具目标还要结合物料抓取关系和工具偏移换算；放料前检查真实物料已到对应位置，不能松爪后再把它瞬移到格子里。

层距定义为相邻两层相同物料基准之间的距离。用户按“物料高度＋隔板厚度＋层间间隙”配置时，由配方编辑器计算最终层距；已直接输入 layerPitch 时不能再重复加一次隔板厚度。非均匀层距需要显式版本化扩展，不能塞入现有单一层距字段。

示例配方：2 行 × 3 列 × 8 层，每层 6 件，共 48 件。具备匹配的 6 抓位工具时，每次搬一层；逐件模式则需要设备和工具能够访问所有目标格。用户只教基准，不需要记录 48 个放料点。

同样的行列层数量不能证明成组搬运可行：固定夹具的各抓位间距必须与当前来源和目标匹配。需要变距时检查实际执行机构及行程；需要转向时检查旋转轴或上游已完成定向。不能靠释放时重新排列物料实现未声明的能力。

#### 9.4 批量、顺序与尾批

首期新模板默认规则逐行、连续占位；继承当前已支持的矩形配方语义。蛇形顺序、隔层转向和自定义格位列表属于版本化扩展，运行器支持后才开放。旋转矩形产品要按旋转后的外形检查托盘边界，不能只改一个角度标签。

成组搬运按显式“抓位 → 来源实体 → 目标格位”映射；一次交接只提交实际到位的整批，单批不跨层。抓位数超出本层剩余容量时等待、改用已支持的较小批次，或报配方不兼容，不能自动挤入下一层。

首期默认要求完整批次。允许尾批必须具备独立抓位控制/确认、明确的空抓位和剩余格映射，且工艺允许；不把机器人示例中的尾批开关直接套到桁架夹具上。部分交接故障保留实际占位和夹持状态，不用失败后的简单计数回滚假装所有物料仍在来源。

当前运行器按数量推导连续格位和层数，不能据此声称已支持任意孔位跳过、自由补格或乱序续码。此类能力需增加明确占位状态，并与同一物料交接记录一致。

#### 9.5 运动轨迹与搬运高度

标准阶段：取料准备 → 在已验证高度移到来源上方 → 垂直下降 → 夹紧/真空确认 → 挂接 → 垂直抬升 → 水平搬运 → 下降到本批目标 → 接触放料 → 垂直回升 → 回程。

生成明确的运动段，升降段锁定水平目标，水平段保持所需升降位置；不能用一次同时改变所有轴目标的 MoveTo 冒充“先抬升、再平移”。当前 moveCartesianTool 会推进所声明的多个轴，应在动作段与求值层共同保证阶段顺序。

搬运高度由已确认的轨迹走廊、沿途障碍物/当前垛顶、夹具及工件最低点和净空要求共同确定。系统可建议高度，用户可以提高或重新选择走廊；低于要求时提示失败，不默默降低间隙。升降行程、上方横梁和工具顶部同时检查，不能只把 TCP 抬得更高。

随码垛层数增加重新计算接近高度和水平搬运检查。不能固定每次下降同样距离，也不能只检查空托盘。无足够空间时保留失败位置，让用户调整布局、层数、夹具或路线。所有“高度通过”结论均绑定当前模型与物料尺寸，不等于全局自动避障。

#### 9.6 隔板、双工具与满托

隔板是一种有真实库存、取料点、夹具和放置目标的物料，复用 Attach/Detach 与接触检查。不得仅用动画出现一块板或计数加一表示已铺好。

界面分别设置“层间隔板”“顶层盖板”和后续可扩展的“底板”，避免含混的“每层隔板”开关。当前合同 layerMaterialRequired=true 的完成条件要求隔板数至少等于层数，即当前 8 层示例需要 8 张，含顶层；若业务只要层间隔板则是 7 张。新增策略必须同步更新配方、目标高度、完成条件和前后端合同，不能只改界面名称。

默认顺序：该层全部产品交接成功 → 产品工具退到停放位 → 隔板工具取板、搬运、接触放置 → 隔板工具退回 → 开始下一层。缺板时显示等待库存，不生成新板冒充实际库存；仿真补料夹具和真实补料反馈明确区分。

两个工具即使使用不同轴也要检查彼此及所持物料。首期按串行互锁运行，共享轴与公共区域只能有一个有效运动所有者；具体 PLC 的安全功能仍由设备控制系统承担。工具“已退回”需要在当前版本中验证实际位置/状态，不能只靠提前写入一个布尔量。

整托完成同时要求：产品数量/占位符合配方、必需隔板已交接、工具未持有应留在托盘的物料、工具退出出料区域、运输条件成立。满足后由现有输送与工位完成机制放行托盘。

#### 9.7 换托盘、任务状态与恢复

建议业务状态：等待空托 → 托盘定位确认 → 码垛中 → 等隔板/层完成 → 整托完成 → 工具退出并允许出料 → 确认托盘离开 → 等待下一托。它们是同一动作流的阶段与状态，不额外建立一个桁架调度引擎。

按实际到位批次和托盘实体锁定目标，禁止默认绑定最近托盘。托盘离位、身份变化或定位信号失效时停止进入新的下降/释放动作，并按照当前持料状态进入等待/故障处理；不能在运动中自动追随另一个托盘。

运行状态至少关联：场景/配方版本、任务标识、目标托盘身份、已占格位或当前受支持的连续数量、当前批次、隔板完成数、当前夹具持料与动作阶段。它们从同一运行实例/物料交接记录产生，不另存一套会漂移的 UI 计数。

换托只在旧托盘退出且新托盘身份及到位成立后开启新任务；不因点击预览或重开编辑器清空现场计数。仿真重置只重建独立仿真状态。中断续码先核对托盘身份、占位、夹持、轴位置和信号，结果不明时不自动重复抓取或重复放置。

#### 9.8 数据和实现边界

基础配方复用 MaterialSlot.stackPattern、stackPatternSlotId、ToolFrame.cartesianActuatorIds、工作点、联锁与动作图。抓位映射、轴角色、隔板策略、可选顺序等新增语义采用明确的版本化合同；生成的每段仍由现有运行器执行。

图纸示例的 48 件、8 张板、两工具、固定 ID、来源坐标及速度只作为迁移案例。新模板必须从用户选定的设备能力和配方生成，不能硬编码到通用模块。

仓库中的 GantryPoseResolver / GantryStackController 分别存在程序化场景或其它运行入口，不能因名称相近就当作本动作流的通用执行器。实施时核对实际入口与所有权，不让旧控制器和新动作流同时驱动同一轴、物料或托盘。

#### 9.9 桁架交付次序

G1：复用共享示教与保存能力，完成桁架轴/工具识别、来源/托盘基准、矩形行列层和整托预览。

G2：完成所选设备实际支持的单件或成组码垛，明确升降/平移段、动态高度、行程及带料检查，跑通一层。

G3：补齐隔板、双工具避让、所有层、满托出料、空托换入和中断恢复，完成整托闭环。

G4：支持其它轴布局、经过适配的变距/旋转/尾批或更多配方，真实 PLC/运动控制器联调按机型独立验收。首版验收设备不支持的能力不能通过增加配方选项提前开放。

## Scope

- Inherit：机器人取放与桁架码垛工艺卡、示教点、可编辑运动段、行列层配方、隔板/换托、同一动作流、分段预览与错误定位。
- Verify：旧 Pick/Place、已有示教 Pose、动态槽位/堆叠、工具占用、限位、两轴成组搬运、旧图纸隔板语义、场景版本往返。
- Exclude：首期全自动避障、任意 GLB 自动变成可求解机器人、多机器人协同规划、运动输送带跟踪、未经适配的真实运动下发。

## Validation

首个机器人闭环使用一个已声明运动学能力的机器人、一个工具、固定来源和固定目标。目标是无需手填 ID/JSON，完成取放点示教、增加途经姿态、分段预览、保存重开和同一流程重放。

桁架闭环使用明确轴与工具的设备，覆盖固定来源、规则托盘、逐批/整层映射、隔板工具和满托换托。新增配置统一保存重开，不能仅用原图纸样例能播放证明通用配置功能完成。

1. 同一取料配置在表单、生成节点与实际运动中含义一致；覆盖 Pick 接近偏移未消费及 liftOffset 缺少表单入口的问题。旧语义修正须有版本兼容与迁移回归。
2. 示教位置和朝向同时可核对，重开场景后引用和轴目标不变；不会选到另一台机器人的轴或工具。
3. 旋转来源台、改变工具姿态后，接近/退出仍沿已声明坐标系方向，相关旧验证作废。
4. 直线模式逐段检查 TCP 线偏差、姿态误差、轴限位和连续性；容差明确保存，不能仅用终点到达证明整段正确。
5. 途经点改变后，去程、回程及带料体积随之重新检查。中间穿过障碍物、不可达或发生关节跳变时定位到具体段。
6. 未夹紧不挂接、无库存不抓取、未接触或容量不足不放料；中断时保留夹持与故障状态，不默认原路退回或丢料。
7. 从非预期初始姿态启动时，拒绝直接跳入已教路径或要求验证入口段；工具缺失、模型不支持的插补模式不可伪运行。
8. 模拟、实时回显、真实任务执行分别验证；浏览器示教操作不能触发真实设备运动。

机器人交付顺序：A. 示教与分段编辑，明确现有关节运动能力；B. 完整工具位姿、直线插补及连续性检查；C. 自碰撞/环境/工件检查与诊断；D. 机型适配和真实控制器联调。A 阶段可以交付编辑与受限预览，不能标记为已完成 B/C 的工业轨迹验证。桁架按 §9.9 的 G1–G4 推进，复用相同基础并分别验收。

实施时执行受影响的运动、物料交接、动作流和限位测试，并新增路径级几何断言；随后验证浏览器的记录、修改、撤销、保存重开。真实设备测试单独记录。本轮没有执行这些尚未实现的验收项。

### 完整验收矩阵

| 任务 | 通过条件 |
| --- | --- |
| 从零配置固定取放 | 不手填 ID/JSON；使用预设点或示教完成点位、方向、距离、途经点和预览 |
| 移动并旋转上料台 | 相对点位正确跟随；旧检查过期；不能直接沿用旧轴解 |

| 路径中间有障碍 | 即使起终点都可达仍报告中段失败；对未配置碰撞体的场景报告检查不完整 |

| 保存、重开、发布 | 数据与节点语义保持一致；旧版本复现不受新模板和新默认值影响 |
| 切换模拟与监视 | 不残留仿真轴值冒充真实反馈，不触发真实运动 |
| 修改过程中重算 | 旧异步结果不覆盖新目标；验证结论与当前版本一致 |
| 视口与错误恢复 | 1366×768 与 1920×1080 可完成主任务；长名称、无解、缺工具、取消选点与未保存离开可恢复 |

### 桁架专项验收

| 任务 | 通过条件 |
| --- | --- |
| 两轴与三轴能力区分 | 当前两轴夹具不出现不可达的逐件/旋转选项，任务由实际能力校验 |

| 2×3×8 成组示例 | 每层 6 件、共 48 件，物料来自实际库存，抓位与格位对应，放料没有瞬移补位 |
| 配方越界与重叠 | 中心距、物料外形、托盘尺寸、总高度不兼容时指出具体层/格或约束 |
| 逐段升降与搬运 | 夹具和工件升至验证高度后才水平运动；后期垛顶、顶部横梁及轴行程也检查 |
| 隔板策略 | 无隔板、仅层间 7 张、每层含顶层 8 张分别按已支持合同生成与判定，旧版本维持原结果 |
| 隔板缺料或双工具冲突 | 正确等待/报错，不凭空补板，不同时侵入互锁区域，不提前放行 |
| 尾批和跨层 | 不支持独立抓位时拒绝不完整批次；不把一批静默分散跨层 |
| 换托与托盘离位 | 目标绑定到位实体，旧托退出、新托确认后才重开任务，离位不误放到其它托盘 |
| 中断续码 | 恢复后身份、格位/计数、隔板、夹持状态一致，不重复交接或清空现场进度 |
| 保存与旧场景回归 | 通用配置可保存重开、重放整托；原图纸流程保留能力且只有一个有效运动执行者 |

除通用动作流、物料交接、限位和流程约束检查外，桁架实施后运行 `npm run verify:drawing-process` 等受影响的整线流程测试，并增加独立配置不同配方/托盘的任务验证。此处为验收计划，本次未执行运动测试或设备命令。

仓库检查入口：`ClientApp` 下 `npm run typecheck`、`npm run build`、`npm run verify:scene-action-flows`、`npm run verify:material-interactions`、`npm run verify:motion-limits`、`npm run verify:flow-safety`。合同变更补后端场景检查器、保存服务与动作流编译/运行回归；浏览器和数据库往返另行验证。本次文档更新不运行未发生变更的产品构建。

## Stop conditions

- 缺少关节层级、轴方向、单位、工具或运动学能力时，只允许模型展示或待配置草稿，不能宣称支持机器人示教轨迹。
- 某段不可达、出现未解决的碰撞或不支持所要求的运动方式时阻止该运行；保留用户编辑并返回具体原因。
