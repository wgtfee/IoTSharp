## 1. 目标与本版决策

默认操作改为：**选择设备、工具、来源和目标 → 引擎生成轨迹 → 查看检查结果 → 必要时调整约束 → 保存工艺**。示教用于修正目标、选择姿态或增加必经点，不要求用户从零配置每一段动作。

“免逐点示教”有明确前提：模型已声明实际运动能力、工具已定义 TCP、取放语义点或工件抓取关系已经准备。引擎根据这些规则计算位置和轨迹；不从任意外观模型猜测可靠抓取面。

| 主题 | V2 决策 |
| --- | --- |
| 机器人与桁架 | 共用坐标、轨迹、检查、动作流；界面按设备能力显示不同配置 |
| 规划方式 | 首期做走廊生成与工具直线；随后增加机械臂自由空间自动绕障 |
| 点位依据 | 明确工具目标或关节目标，一次只允许一种权威来源 |
| 执行连接 | 新增版本化 FollowTrajectory 节点消费规划产物，纳入现有动作流调度 |
| 存储依据 | 工艺卡编辑同一份节点与引用；轨迹是版本绑定的派生产物，不另存第二份可编辑流程 |
| 速度与连续性 | 在可运行仿真交付时具备；不拖到自动绕障阶段才补 |
| 动态码垛 | 发布固定工艺、配方和允许的动态范围；每批生成自己的轨迹与记录 |
| 兼容 | 旧 Pick/Place 运行语义保持；新向导生成显式运动与交接，迁移可选 |
| 首期执行位置 | 浏览器 Worker 规划、同一求值器预览与仿真；后端验证合同、引用和产物一致性 |
| 真实设备 | 经独立机型适配和控制器验证，沿用现有设备命令边界 |

先覆盖当前内置机械臂和图纸桁架各一个明确能力范围。桁架整托交付不等待任意六轴机型求解器，也不把所有导入模型视为可规划设备。

## 3. Design decision：用户流程与界面

### 3.1 机器人取放

1. 选机器人、工具、来源物料位和目标位置。唯一且兼容的预设点自动带入，多个候选交给用户选择。
2. 确认取放方向与物料抓取关系，默认沿用已验证的组件/工艺模板。高级区可改目标姿态和约束。
3. 点击“生成轨迹”。系统生成接近、抓取后退出、搬运、放料后回撤和回程；同时显示各项检查状态。
4. 逐段预览。失败时显示具体段、位置及原因，并提供调整目标、允许范围内增加净空、选择姿态或添加必经点的入口。
5. 保存工艺。中间态可以存草稿；通过运行检查后才能进入对应的可运行仿真。

### 3.2 桁架码垛

选桁架与工具 → 确认取料基准和托盘坐标 → 填行列层、批量与隔板规则 → 自动生成运动 → 切层/整托预览 → 保存工艺。行列层计算、满托和换托细节见 §9。

### 3.3 工作台结构

保留现有工程画布和 Element Plus 组件。左侧显示任务配置，中间显示三维与路径，右侧编辑选中的点或段，底部显示阶段、检查结果和等待原因。三维/动作图/分屏属于布局选择，不改变运行模式。

```text
设备 / 工艺名       草稿状态       保存草稿  生成轨迹  仿真预览
左侧：设备与工具、来源与目标、运动约束、码垛配方、信号
中间：三维对象、候选目标、方向、实际路径、当前物料状态
右侧：当前点或运动段的参数、依据、检查结果与定位操作
底部：阶段条、逐段播放、诊断、可展开的同一动作图
```

一次拖动形成一个撤销步骤；取消选点不污染已有定义；切换设备或布局保留草稿。错误同时用文字和图标表达，技术 ID 和节点路径只在高级详情出现。窄视口可折叠面板，不能挤掉三维操作区。

M1 的“路径预览”允许通过滑块检查几何路径，无节拍承诺；M2 的“仿真播放”才消费带时间且通过对应检查的轨迹。进度拖动只重建隔离仿真状态，不改现场库存或发设备命令。

## 4. 位置、姿态与权威来源

### 4.1 四种位置入口

| 入口 | 行为 | 权威来源 |
| --- | --- | --- |
| 预设点 | 选组件的抓取位/放料位，必要时调整实例偏移 | 工具目标 |
| 三维点选 | 点击允许的对象表面，显示候选位置与方向，再确认 | 工具目标 |
| 调轴记录 | 调仿真轴或读取有效反馈，记录当前姿态 | 关节目标 |
| 数值输入 | 明确参考对象与单位后编辑工具位置/角度或关节值 | 取决于当前目标类型 |

鼠标点选用位置与表面法线提出候选，不能自动确认工艺抓取关系。必须区分工件特征点、夹具 TCP 和支撑面；只获得表面法线还不能确定绕接近方向的转角。

### 4.2 显式目标类型

采用带判别字段的目标引用：`teachType=toolTarget` 引用 WorkPoint；`teachType=jointTarget` 引用 Pose。工具位姿和轴目标分别由现有定义保存，不在工艺卡重复存一份可冲突值。此结构是拟新增合同，命名在 M0 对齐现有类型。

- 工具目标以参考对象下的位置、朝向和允许误差为准，关节解为派生结果；求解分支提示单独记录。
- 关节目标以 Pose 轴值为准，工具位姿由正向运动学产生用于核对。
- 调轴记录后转为工具目标，或对关节目标直接编辑 XYZ，均显式转换并显示差异。数值输入本身不被禁止，输入单位和当前目标类型必须一致。
- 拖动工具目标由求解器预览整台设备，不把末端网格拉离机械臂。无解保留候选和原因，不跳到伪造姿态。
- 反馈来源、时间、模型和工具版本必须可追溯；不完整或过期反馈不能标为当前示教姿态。

### 4.3 坐标与必经约束

取料点相对来源，放料点相对托盘/定位座，TCP 相对工具；对象移动后换算世界位姿，再求关节解。记录的固定关节姿态不会自动跟随台面移动，依赖它的段需要重查。

参考对象、可选模型节点、轴方向、单位和旋转顺序须明确。场景 Y 向上不代表现场升降轴也命名为 Y；不得把方向写死为工具 Z。现有动态槽位的坐标分支在 M0 单独回归，不静默改变旧解释。

首版只提供明确的“必经姿态/点”，不混用含义模糊的软提示。用户添加后，规划段按该约束拆分；首版在约束点停止。删除约束后重新规划受影响连接及其后续状态依赖，不能承诺其余路径完全不变。

## 5. 能力、碰撞几何与参数来源

能力按正交字段声明，而不是凭一个等级放开所有功能。

| 能力维度 | 必需声明 | 未具备时 |
| --- | --- | --- |
| 轴与几何 | 层级、零位、单位、行程、尺寸、正向运动学 | 仅展示或待配置 |
| 工具目标求解 | 平移轴映射或 IK；允许的姿态约束、求解器版本 | 可以关节示教，不能承诺工具目标求解 |
| 朝向 | 固定朝向、方向约束、完整旋转等明确种类与容差 | 隐藏不支持的配置，或保留待配置错误 |
| 运动时间 | 轴速度/加速度、同步策略、插补器和版本 | 只允许几何预览 |
| 碰撞 | 机器人各链接、工具、工件和环境的覆盖集合/模型版本 | 不显示碰撞已检查 |

完整位姿求解表示可处理完整位姿约束，并不意味着任何目标都可达。当前内置机器人暂不标记为完整 6D，须用具体目标集合确认能力。两轴桁架只能在声明的轴与夹具范围内求目标；成组搬运不能伪装为任意逐件定位。

碰撞几何分 K0 未配置、K1 模板简化体、K2 已说明精度范围的模型。K1/K2 还必须声明覆盖对象、排除对与检查分辨率；等级本身不证明全场景覆盖。

组件维护者提供版本化默认盒体/胶囊/凸包，场景编辑者可查看与校准；模型、工具、物料或变换改变使相关结论过期。只按明确的关节拓扑和接触阶段排除指定碰撞对。工件挂接后进入移动集合，放下后进入环境集合。

参数来源固定为：用户任务覆盖 → 已验证工艺模板 → 已验证机型配置 → 待配置。约束性参数不能来自无声兜底。模板维护者负责机型/工具/物料组合的参数验证，任务编辑者确认其适用性；保留来源与版本。

用户建议中的 1 mm、1°、50 mm、100/250/150 mm 等数值不设为通用生产默认值。开发用合成夹具可有明确数值配置，但必须标记 testOnly，不能随新场景自动发布。采样精度还需考虑全链接转动扫掠与薄障碍物，不能仅用 TCP 平移步长判断。

## 6. Changes：规划器与检查规则

### 6.1 三种规划器

| 类型 | 自动生成什么 | 适用段 | 约束 |
| --- | --- | --- | --- |
| corridor | 在已允许走廊内生成抬升、搬运和下降段，可有界提高净空 | 桁架；已适配机械臂的候选搬运段 | 机械臂仍检查肘部/各链接，不能把“工具抬高”当作整臂避障 |
| linear | 工具沿规定路径接近/退出，逐步求解并保持指定姿态约束 | 取放接触前后 | 无解或不连续时失败，不改成另一种运动继续 |
| sampled | 在关节空间寻找自由空间连接，首选评估 RRT-Connect | 机械臂搬运与回程 | 具备完整 FK、有效目标解和碰撞集合；不用于接触段 |

规划器采用统一请求/结果结构。K0 下 corridor/linear 仅能给出未碰撞检查的几何预览；sampled 不开放。K1/K2 下也只有所需对象都在检查范围且最终轨迹通过检查，才标记碰撞项通过。

机械臂标准任务：入口 → 预取 → 直线接触 → 夹紧确认 → Attach → 直线退出 → 搬运 → 预放 → 直线接触 → Detach → 直线回撤 → 回程。取放接触点不做圆角过渡。初始姿态和回程路径均纳入规划，不默认从一个已验证待机点开始。

### 6.2 有界调整与失败

生成前声明允许调整的范围：备选关节分支、净空上限、接近距离范围和可用规划器。锁定姿态/距离不得自动改动；“固定”与“允许在范围内调整”在界面区分。

在允许范围内依次尝试备选分支、走廊候选/净空、自由空间采样连接。调整了接近距离后重新检查整个相关接触链，不移动已经确认的接触目标。成功结果显示采用的实际参数和调整原因。

无解、碰撞、超限、预算不足和模型缺项分别报告。超时不等于不可达；部分路径只能用于诊断，不能当作完整成功。任何失败都保留草稿，不降级为未经检查的运动。

### 6.3 连续性、时间与最终验证

M1 生成几何路径；M2 为每段增加时间，并同时验证轴位置、速度、加速度、关节连续性、工具偏差与碰撞。首版段间停止，避免先引入跨段混合带来的复杂性；不宣称具有未实现的 jerk/动力学约束。

工具直线的关节样本之间如何插值必须属于同一求值合同。检查真实插值后的工具偏差和链接扫掠，不能只检查采样点。路径缩短、重采样或时间处理如果改变几何，就重新进行所有受影响检查。

工程依据：官方文档区分几何规划和轨迹时间处理，且指出部分时间处理的重新采样可能需要补充碰撞检查；本方案据此要求对最终执行表示验证。[MoveIt 时间参数化说明](https://moveit.picknik.ai/main/doc/examples/time_parameterization/time_parameterization_tutorial.html)

检查分四项：**配置完整、运动可解、碰撞检查、交接模拟**，各自有未检查/通过/失败/已过期。运动项包含可运行版本所需的时间与轴约束，并显示几何检查与时间检查子项。M1 不承诺四项全通过；M2 可运行任务必须满足其完整检查要求。

碰撞采用全链接、工具和工件检测。M2 最低要求保守模型和自适应细分/明确的运动验证策略，结果报告覆盖与分辨率；不能把有限采样描述成对任意几何的无碰撞数学证明。

### 6.4 确定性、性能和取消

Worker 接收不可变输入快照和递增请求序号。旧请求取消或完成后结果被丢弃，不能覆盖新目标。拖动时可降采样预览，但最终确认必须执行规定精度的验证。

需要重复规划一致性时固定：随机种子、迭代/扩展次数、遍历顺序、求解器/规划器/插补器版本及数值环境。墙钟超时用于中断保护，不把“同 seed＋相同秒数”作为路径一致保证。

回放优先使用已保存的同一轨迹产物与其求值器版本，不重新抽样来冒充回放；跨运行环境的数值等价按记录容差检查。缓存记录输入摘要、结果哈希、算法预算和检查覆盖，几何预览缓存不能被当作可执行轨迹。

算法选型参考 [OMPL 规划器目录](https://ompl.kavrakilab.org/core/planners.html) 和 [终止条件接口](https://ompl.kavrakilab.org/classompl_1_1base_1_1PlannerTerminationCondition.html)。M4 先比较已有可复用实现与适配成本，再确定 TS/WASM 等交付形式；本规划不预先引入 ROS 服务或未经评估的依赖。

## 7. 从规划到执行：一条明确链路

### 7.1 数据各有归属

| 数据 | 权威位置 | 用途 |
| --- | --- | --- |
| 工具、工作点、关节目标、槽位 | 现有 ToolFrame / WorkPoint / Pose / MaterialSlot | 用户可编辑的定义，保留稳定 ID |
| 运动段目标、规划方式和约束 | 同一动作流节点的版本化配置 | 工艺卡读取/修改这些值，不再保存一份独立任务副本 |
| 配方和动态规则 | 版本化码垛定义与节点引用 | 生成当前批次的目标，规则本身属于发布配置 |
| 工艺卡关联信息 | 作者元数据 | 仅保存模板版本、节点归属、字段映射、生成基线，不独立执行 |
| 几何路径/带时间轨迹 | 不可变规划产物 | 派生数据；通过哈希和输入摘要绑定，不能直接编辑后仍沿用检查结果 |
| 本次执行绑定与事件 | 运行实例 | 记录节点使用哪个产物、当前物料/托盘、版本和结果 |

向导输入是生成/修改同一图的事务请求。生成后节点及其引用定义是唯一可编辑依据，工艺卡是其投影。高级图结构修改后进入自定义状态；重新套模板需显示差异，不能覆盖手工分支。生成、改点和关联修改须一次撤销并完整保存往返。

### 7.2 新增 FollowTrajectory 节点

选择显式新增 `FollowTrajectory` 动作节点，不把规划路径塞进旧 MoveTo 后仍调用旧终点运动逻辑。名称和字段是本规划拟定的合同，当前代码尚不支持。

节点属于现有 Action Flow V2，由现有调度、Actor 所有权、超时、故障与事件机制管理。首期仅允许 `executionTarget=scene`；独立图运行器和真实执行端在未适配前明确拒绝。

新节点同时加入现有运动类节点的校验约束，失败不得通过 skip 或伪成功继续交接；重试前须重新核对起始状态和所用产物。M0 只交付可保存/校验的合同，运行能力在 M2 消费链完成后才对外声明支持。

节点配置保存运动合同版本、阶段角色、目标引用、规划配置引用、强制途经约束、物料状态要求和允许的动态参数。每批产物绑定保存在运行实例，不在运行中改写已发布节点。

示意结构，实际 DTO/类型在 M0 前后端同步确定：

```ts
type MotionTargetRef =
  | { teachType: 'toolTarget'; workPointId: string }
  | { teachType: 'jointTarget'; poseId: string };

interface TrajectorySegmentSpec {
  contractVersion: 'motion-segment/1';
  role: 'entry' | 'approach' | 'lift' | 'transfer' | 'retreat' | 'return';
  toolFrameId: string;
  target: MotionTargetRef;
  plannerProfileId: string;
  requiredPayloadState: 'empty' | 'holding';
  // 约束采用有类型的合同；坐标、限值、接触集合不得藏进任意脚本。
}

interface ExecutionPlanBinding {
  executionId: string;
  nodeId: string;
  policyDigest: string;
  runPlanDigest: string;
  artifactHash: string;
}
```

产物还需包含轴 ID 顺序/单位、起终状态、位置/朝向约束、带时间的轨迹表示及插值约定、模型/工具/物料快照标识、检查结果与覆盖、算法和求值器版本。时间数组单调，数值有限，轴身份和范围可验证。M1 几何产物显式标为不可执行，没有时间不能伪装成 duration=0 的成功动作。

### 7.3 运行器必须实际消费轨迹

```mermaid
flowchart LR
    A[工艺卡与已有定义] --> B[同一动作流的运动段]
    B --> C[冻结输入并规划验证]
    C --> D[不可变轨迹产物]
    D --> E[预览求值器]
    D --> F[FollowTrajectory 执行器]
    F --> G[现有执行轴写入通道]
```

执行步骤：

1. 节点取得同一 Actor/轴资源所有权，核对工具、持料状态、起始姿态、环境和发布策略。
2. 选择匹配的已存产物，或按 §8 在允许的批次边界规划新产物。缺少、过期或检查不足时等待/失败，不转去执行旧 MoveTo。
3. 通过与预览相同的求值器按仿真时间计算目标轴值，写入统一轴通道；原有终点追踪器不得再次改变该轨迹的时间和路径。
4. 任意时刻只有一个有效轴驱动源。轨迹、旧目标控制和实时遥测之间显式切换，防止下一帧覆盖轨迹结果。
5. 结束时核对实际终态与记录容差，才让现有动作流推进。GripClose、Attach、Detach 仍由已有交接逻辑执行，并触发下一阶段的物料碰撞集合变化。

夹紧/挂接前后的规划输入必须包含真实或隔离仿真的物料状态；预先按预计工件规划的产物，只有实际物料类型、尺寸、抓取变换和数量匹配才可用。否则在下一运动前重新验证。

暂停时固定仿真时间与物料状态；恢复时检查输入是否改变。修改场景或重置后不能从旧曲线中间强行继续。仿真进度回看使用独立状态，不对主运行实例重复触发 Attach/Detach。

### 7.4 保存、发布与后端责任

M0 同步升级前后端动作类型、支持集、配置验证、Manifest 归一化、保存和版本读取，声明所需运动合同版本。现有 `schemaVersion` 归一化路径须检查不会丢弃新字段；只增加前端字段不算完成。

后端至少验证：租户和资源归属、引用存在与所属设备、支持版本、节点到产物的绑定、规范化内容哈希、有限数值/轴单位/时间结构、大小与点数限制，以及发布条件。不能只检查摘要字符串长得像哈希，就把前端的“通过”视作可信证明。

首期后端不复制一套 C# 路径规划器。浏览器碰撞结果标明为编辑器仿真证据，服务端结构验证不冒充独立碰撞证明；真实执行在 M5 由可信设备/控制器侧另行验证。若后续需要服务端物理验证，优先复用同一规划核心或受控规划服务。

轨迹产物属于版本化资源，发布场景的静态产物随发布快照绑定；动态产物随运行记录保存。可淘汰普通编辑缓存，但不能删除仍被发布或回放记录引用的产物后悄悄重算替代。找不到产物或匹配求值器时显示不可回放/需重新验证。

## 8. 发布策略与动态码垛

### 8.1 区分三种摘要

| 标识 | 内容 | 改变的含义 |
| --- | --- | --- |
| policyDigest | 已发布图、工作点/工具、配方、静态场景与碰撞模型、机型/算法版本、允许动态输入及边界、校验配置 | 配置变更，需要新草稿和重新发布 |
| runPlanDigest | 上述策略 + 本批起始姿态、绑定托盘/物料、占位/层号、实际参考变换与障碍快照 | 本次运行条件不同，需要匹配的本批规划 |
| artifactHash | 实际轨迹内容、时间表示、检查结果及求值版本 | 用于完整性校验与准确回放 |

规范化与哈希算法纳入合同。碰撞数据、接触排除规则、轴单位、参数和版本变化都影响相应摘要；不能只记录终点坐标。

### 8.2 两种明确的发布方式

**固定轨迹**：发布时绑定已验证产物。运行的起始状态和环境在记录容差内匹配才能复用；超出则阻止该段并说明差异，不自动找另一条路线。

**受限动态工艺**：发布固定配方/约束及允许变化的输入，例如层号、托盘实例、到位基准在声明范围内的变化、已知工件规格和期望占位。每批按当前状态生成新的 runPlanDigest 和产物，校验通过后绑定到该运行实例；发布配置和版本不变。

规则码垛使用第二种方式，避免把正常升层当作发布失效。范围外的工具变化、未知障碍、未经声明的工件尺寸或随意移动工位，不属于已允许的动态变化。

不使用一个含义过宽的“允许运行时重规划”开关。策略要写清可变参数、范围、规划器、调整上限和检查等级；默认固定，码垛模板明确声明受限动态。

### 8.3 运行边界与回放

首期只在动作开始前或已停止的批次边界规划，目标在一段运动期间冻结。物料挂接、托盘换入和铺板等预期状态转换触发下一阶段的输入更新。障碍或目标在运动中发生未声明变化时进入停止/故障处理，不边运动边临时改路。

回放记录策略版本、物料/托盘身份、输入快照、所用产物哈希、时间基准和交接事件。复现时使用当时产物；重新规划得到相似路径不能标为原运行回放。规划成功与库存提交是不同事件，只有实际交接成功才更新占位。

## 9. 桁架码垛完整流程

### 9.1 配方与位置

用户确认实际横移/纵移/升降/旋转轴及夹具，示教来源基准、托盘原点与方向、首件或首组放置基准。配置行列层、中心距或净间隙、首层高度、层距、批量、放置次序和隔板策略。

规则格位沿用现有局部坐标计算：列沿 X、行沿 Z、层沿 Y 的适配中，位置为 `[originX+c×spacingX, firstLayerY+l×layerPitch, originZ+r×spacingZ]`。轴角色与坐标必须按模型明确声明，不推广成所有现场的轴命名。

公式得到物料基准，不直接等于 TCP。结合实际抓取变换计算工具目标，并检查放料前物料已到对应格位。中心距、物料边界和托盘外形一起检查；层距若已包含隔板厚度，不能重复叠加。

两轴固定多抓位夹具只开放可实现的成组/整层搬运；逐件全空间定位、变距或交错转向要求对应的轴与工具能力。首期规则逐行连续占位，不承诺任意孔位跳过、自由补格或一批跨层。

### 9.2 每批自动轨迹

等待来源和目标许可 → 提升至已验证搬运高度 → 移至来源上方 → 下降接触 → 夹紧/真空确认 → Attach → 垂直提升 → 水平搬运 → 下降至本批目标 → Detach → 回升 → 回程或隔板任务。

升降段锁定水平目标，水平段保持所需高度，均通过 FollowTrajectory 的显式段执行。不能一次推进多个轴，再把结果称为“先升后移”。

搬运高度根据走廊障碍、当前垛顶含隔板、夹具与工件下沿、净空要求共同生成候选；同时检查工具顶部、横梁和升降行程。有顶棚或夹具形状复杂时，仅用一个高度公式不足以证明路径通过，仍走同一全段碰撞检查。

每层每批按受限动态策略重新求值。目标托盘通过到位批次/实体锁定，不能自动绑定最近托盘。目标离位或身份改变时不继续下降释放。

### 9.3 隔板策略与层高

拟新增显式 `separatorPolicy`，前后端、流程生成、目标高度和完成判断一起适配。

| 策略 | L 层需要的板数 | 当前基础与迁移 |
| --- | --- | --- |
| none | 0 | 底层已有“不要求隔板”的完成条件；新模板还需取消铺板任务并校验配方 |
| interlayer | max(L−1, 0) | 新语义，须扩展合同与层完成条件 |
| interlayer+top | L | 与当前 layerMaterialRequired=true 的含顶层示例对应 |

2×3×8 示例共 48 件：无板为 0 张，仅层间为 7 张，含顶层为 8 张。旧数据 true 保留原含义；false/未指定保持原完成判定。若旧图里存在额外手写铺板动作，迁移必须显示差异，不能只改一个字段推断全部工艺。

层距的计算来源明确：用户按物料高度、板厚和间隙填写时生成对应层距；直接输入层距时不重复加板厚。不等高层或非均匀隔板布局属于后续明确合同扩展，不塞入一个固定 layerPitch。

隔板有库存、来源、工具和接触目标。当前层放完 → 产品工具退出 → 取板铺板 → 隔板工具退出 → 下一层。缺板等待，仿真补料与实际库存分开。

### 9.4 批次、双工具和换托

每个抓位明确映射到来源物料和目标格位；首期要求完整批次。尾批需要独立抓位能力和确认；单批超过本层剩余容量时不静默分散到下一层。

双工具共用碰撞集合，并使用资源所有权和区域互锁保证执行顺序。碰撞检查不能替代调度互锁；首期串行，工具已退出要由实际位置/状态验证，不只依靠提前写入布尔值。

整托完成要求产品占位、必需隔板、工具持料状态与出料区域全部符合配方，再通过现有工位/运输机制放行。旧托确认离开、新托身份及到位成立后才开始新任务。

状态链：等待空托 → 定位确认 → 码垛 → 层完成/铺板 → 满托 → 工具退出 → 出料确认 → 下一托。使用同一动作流状态与物料记录，不另建一个桁架调度器。

中断恢复核对托盘身份、占位/当前受支持的连续数量、隔板数、当前批次、夹持和轴位置。结果未知时等待核对，不自动重抓、重放或清零；仅重开编辑器不能改变现场进度。

## 10. Reuse、兼容与系统边界

复用 SceneManifest、WorkPoint、Pose、ToolFrame、Actuator、MaterialSlot、Action Flow V2 及现有物料交接、Actor 所有权和设备命令适配。FollowTrajectory 是同一动作流的新执行原语，轨迹求值器是运动模块，不接管任务调度。

旧 Pick/Place 的执行行为保持。旧 Pick 中无效的接近字段明确标为未消费；新工艺使用 FollowTrajectory + GripClose/Attach/Detach。升级操作创建草稿、展示动作与运动差异、重查并生成新版本，已发布版本不自动迁移。

入口清点属于 M0：列出 SceneActionFlowRuntime、旧 Behavior、GantryStackController、GantryPoseResolver 所在程序化场景及实时反馈各自控制哪些轴/物料。按实际运行入口建立唯一所有者，不能因同名就混用不同场景的控制器。

编辑草稿与可运行投影分层，允许语义未完成的草稿持久化；租户、引用归属、文件大小和结构校验仍保留。错误草稿不能复用上一次成功投影冒充当前可运行内容。共同依赖未落地时，在 M0 完成满足本任务的最小版本，不通过绕过发布校验解决。

仿真只驱动隔离状态；实时监视只读设备反馈；真实执行通过既有 Gateway/设备适配和控制器程序，单独验证机型、坐标标定、工具、程序版本、幂等和恢复。场景仿真发布不等于批准真实运动。

## 11. 一套里程碑 M0—M5

| 阶段 | 交付内容 | 完成条件 | 依赖 |
| --- | --- | --- | --- |
| M0 合同与基础 | 目标类型、机型/工具能力、运动合同与支持集、轴控制入口清点、参数来源、最小草稿保存 | 新合同可保存重开，旧语义回归，能力缺项明确，前后端不丢字段 | 通用编辑保护的最小子集 |

M3 与 M4 可以分别开发和验收，但共享的运动合同变更必须统一版本。两条线都不使用新的阶段编号。

首个完整纵向交付为 **M0–M2 的最小场景**：内置机械臂一个已确认朝向范围、桁架一个已确认轴布局，各有固定来源/目标、已准备的工具和物料。环境包含料台与一个可移动的障碍测试对象；其它显示模型的碰撞覆盖必须如实列出。

该交付必须包含最小时间与执行链，不能为了缩短首期把 FollowTrajectory 或时间约束留到 M4。验收先证明自动生成、执行一致、障碍失败定位、保存重开；不要求首期必定自动绕过立柱。自动绕障是 M4 的独立可见能力。

旧编号对照：W0→M0；W1→M1；W2/W3 与 A/B/C 的运动部分→M1–M2；W4→M0–M3 按实际功能落地；W4G/G1–G3→M1–M3；采样能力→M4；W5/D 及真实设备扩展→M5。旧编号不再用于新增任务跟踪。

## 14. Scope、Stop conditions 与不变量

范围包含：内置机械臂的已声明能力、当前桁架轴布局、自动候选与受检查的轨迹、码垛隔板与换托、同一动作流和独立仿真。

范围之外：任意 GLB 自动成为可求解机器人、无声明场景的通用抓取识别、输送带运动跟踪、多机器人并行协同规划、完整动力学与任意厂商程序自动导出。真实机型扩展按 M5 单独定义，不占用仿真通过结论。

| 编号 | 所有阶段必须保持的规则 |
| --- | --- |
| INV-1 | 只有一份可编辑且可执行的动作图；工艺卡是它和既有定义的视图 |
| INV-2 | 每个目标只有一种权威依据，转换显式，引用稳定 |
| INV-3 | 规划产物不可编辑，绑定输入与版本；执行实际消费该产物 |
| INV-4 | 预览和执行同源求值，轴只有一个有效控制者 |
| INV-5 | 检查分项、可过期；失败/缺覆盖不降级伪通过 |
| INV-6 | 正常动态输入与配置变化分开，发布策略和本次产物分开 |
| INV-7 | 库存、夹紧、接触和放料据实际状态，不能瞬移或伪造交接 |
| INV-8 | 旧版本语义保持，新语义在所有消费者支持后才开放 |
| INV-9 | 仿真、监视和真实执行隔离，现场结果单独验证 |

遇到缺少运动/碰撞模型、未经验证的目标约束、不支持的合同版本或产物失效，停在对应任务/阶段并保留草稿和诊断；不要把无解改成成功或重置物料。若需要扩大机型、现场控制或算法依赖范围，先形成具体适配子计划，不在当前模板里隐藏实现差异。
