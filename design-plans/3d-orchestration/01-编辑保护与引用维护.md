# 编辑到一半也能保留，修改关联不要求返工

日期：2026-11-05。Written against：`Develop / 4d3b7feb`。状态：待实施。

## Evidence chain

- Surface：`/iot/digital-twin/workbench` 的新建、保存、切场景、删除对象和数据绑定。
- Problem：空白路线校验与创建模板冲突；所有 error 阻止草稿保存；切场景直接换 Manifest；删除设备/绑定没有统一处理引用。
- Evidence：`ClientApp/src/digital-twin/contracts/index.ts:733–765,1284–1285`；`ClientApp/src/views/iot/digital-twin/workbench.vue:1876–1896,1994–2005,2263–2282,2330–2389`；`IoTSharp/Services/DigitalTwin/DigitalTwinSceneService.cs:124–129,230–232,264–279`。
- Runtime：模板经 `digitalTwinApi.createScene` 原样送入服务端；服务端创建、保存都会调用 Inspector 后 ThrowIfInvalid。删除绑定按钮直连 removeBinding，删除对象直连 removeModelObject。
- Scope：工作台及共享草稿/发布合同；场景中心、3D/2D Viewer、2D 编辑器、Action Flow 服务列为回归对象。
- Uncertainty：已做源码和内存专项复现；真实接口错误呈现、数据库往返、跨标签页冲突、浏览器恢复待实测。本计划是用户要求的流程与功能改进，不以源码推断视觉拥挤。

## Design decision

明确三个不同门槛：可保留编辑、可启动模拟、可发布。草稿允许业务配置未完成；发布、真实执行仍要求完整引用、资源权限、可执行计划和既有安全规则。任何自动恢复都不会发布或启动设备。

编辑状态由同一场景会话维护：场景 ID、本地草稿 ID、服务器基线 revision、当前修改序号、最近成功保存的修改序号、恢复时间。运行快照、相机浏览和瞬时选择不作为业务未保存修改。

## Reuse

- `validateTwinSceneManifest`、`TwinManifestInspector`、`TwinActionFlowServerCompiler` 的规则和诊断编号；不是删除这些校验。
- `diagnosticLocator.ts`、现有 diagnostic path 定位。
- `TwinOrchestrationDesigner.ts` 的定义操作和工作台历史入口。
- `component-studio.vue` 已有本地保存/恢复交互可作为文案参考；不沿用它的单一全局 localStorage key。
- 拟新增 `ClientApp/src/digital-twin/authoring/SceneDraftSession.ts` 和 `SceneReferenceIndex.ts`。当前删除逻辑分散且仅覆盖部分引用，现有单项删除函数不足以提供跨对象影响分析。

## Changes

### 1. 空白场景和保存门槛

Owner：`contracts/index.ts`、`workbench.vue`、`editor-adapter/*`、`routes/*`、`DigitalTwinSceneService.cs`、`TwinManifestInspector.cs`。

- 空白 Manifest 使用 `routes: []`。只在用户创建路线或组件生成路线时加入真实路线，不为了过校验放置虚构点。
- 清理 normalizeManifest 强制补零点路线的逻辑。检查所有实际运行路径上的 `routes[0]`，没有路线时显示“添加路线”空状态，隐藏/禁用路线测试，允许编辑静态模型。
- 将校验目的显式区分为 DraftSave、Simulation、Publish。保留非法 JSON、合同版本、类型/大小限制、租户及资源访问权限等保存门槛。
- 未选 Actor、未补工作点、图未连完等属于可保存的编辑诊断；模拟和发布时仍阻止执行。错误不是被吞掉，而是带着准确位置保存并展示。
- 服务端的 DraftPayload 是编辑内容权威。完整且可编译时按现有事务重建绑定、路线和动作流投影；未完成时保存合法的编辑载荷及校验摘要，清除旧草稿执行投影，不留上一版可运行数据伪装成当前草稿。
- 发布从当前 DraftPayload 重新全量校验、编译并创建不可变版本。已发布投影不随草稿变化。
- 草稿 Viewer 和运行入口看到不可运行状态应显示诊断，不能悄悄读取旧计划。API 返回草稿校验状态和诊断；旧前端/后端混合部署需明确兼容与功能开关。
- 为草稿诊断/可运行状态建立明确存储和 DTO 合同；若需新增字段，提供项目支持的数据库迁移及迁移验证，不临时把诊断塞进业务名称或状态字符串。

### 2. 未保存保护和恢复

Owner：`workbench.vue`、拟新增 `SceneDraftSession.ts`。

- 顶部显示未保存、保存中、已保存时间、保存失败；线上版本状态单独显示。
- 切换场景、创建另一场景、离开工作台统一经过“保存后继续 / 保留恢复副本后离开 / 取消”。保存失败时停留，不继续导航。
- `beforeunload` 在存在未保存编辑时启用；浏览器原生退出提示只是补充，不能当作恢复机制。
- 使用 IndexedDB 保存经过允许字段筛选的恢复副本，按登录主体、租户、场景 ID 或本地草稿 ID 隔离。只存定义及资源标识，不存 GLB 二进制、遥测历史、令牌或凭据。
- 编辑事务后防抖保存；处理配额不足和写入失败并显示恢复状态。重新进入时比较基线 revision，让用户查看并恢复本地副本，绝不自动覆盖新服务器版本。
- 未入库内容可通过保存入口完成命名和根 Asset 选择，沿用当前内存内容创建；不能换成另一个空白模板。
- 根 Asset 仍属于业务范围；资产不存在时保留本地内容并提供返回路径，不要求用户重新搭建。

### 3. 删除与引用维护

Owner：`workbench.vue`、`TwinOrchestrationDesigner.ts`、拟新增 `SceneReferenceIndex.ts`。

- 索引对象、资源、端口连接、路线点/边/区段、工作点、槽位、TCP、轴、姿态、绑定、Behavior、Action Flow、联锁和托盘初始化器中的结构化引用。
- 仅识别合同中的引用字段；不可对任意字符串全局搜索替换。
- 删除前展示影响摘要：设备自身定义、外部流程节点、路线附件、共享绑定。自身附属项随设备清理；外部消费者必须解除、换绑或明确保留为待配置。
- 被引用的高层流程不静默删除。暂不能完成重绑定时允许保存待配置草稿，并阻止有关模拟和发布。
- 删设备、相关定义清理和外部引用更新构成一次事务，撤销完整恢复稳定 ID、几何变换、引用和连线。
- 自动路线的重建应在删除对象后发生，避免仍用待删除对象生成路线；手工路线与附件按现有创作来源分别处理。

### 4. 原位编辑绑定

Owner：`workbench.vue` 的 binding-form/list、`ComponentPropertyPanel.vue`、拟新增绑定编辑服务。

- 编辑 Key、设备、单位换算或 stale 参数时保留 bindingId；复用校验，不走删除再新增。
- 更新前验证新数据源在当前权限范围内、目标类型兼容；展示受影响消费者及最新样值。
- 删除绑定必须覆盖全部路线、Action Flow、组件 slot、联锁、轴和初始化器引用。不能仅处理第一条路线。
- 用户可撤销整次编辑；批量换绑逐项给出匹配结果，先预览再一次应用。

## Scope

- Inherit：共享草稿合同的 3D 和 2D 编辑器、发布、场景中心。
- Verify：不可变线上版本、回滚生成草稿、服务端 Action Flow 启动门槛、多标签页并发、不同租户恢复副本隔离。
- Exclude：真实运行的故障自动恢复、设备命令重试策略、控制系统改造。

## Validation

产品任务：空白创建→放模型→未连完动作→保存→关闭→重开，内容一致且明确不可运行；改 Key 不丢规则；删设备后无未提示悬空引用，撤销恢复；旧线上版本保持原行为。

接口：验证无路线场景、缺少 Actor 的草稿、无权限真实资源引用、非法合同、版本冲突、网络响应丢失、保存期间继续编辑。安全/授权错误不能被“草稿模式”绕过。

## Stop conditions

- 若下游直接把所有草稿投影当作可运行权威，先统一执行准入再开放半成品服务端保存；期间仅上线明确标为本地的恢复副本，不声称已保存服务器。
- 若某引用不在结构化合同内，记录并补充显式协议，不进行字符串猜测清理。

## Design documentation

实施验收后，在现有动作流优化方案中记录三个保存/运行门槛、引用删除语义和恢复范围；本规划阶段不改原设计文档。
