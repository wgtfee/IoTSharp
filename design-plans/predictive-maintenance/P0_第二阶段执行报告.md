- IoTSharp/appsettings.Development.json 的 IoTSharp、TelemetryStorage、EventBusStore 使用非本机 SQL Server 连接，数据库名称未明确标为 dev/test；因此没有盲连、没有执行 SQL，也没有暴露连接信息。
- appsettings.Sqlite.json 和 appsettings.InfluxDB.json 的 SQLite 文件在常规相对路径下不存在；不能从空项目文件推断有真实设备数据。
- 真实 Product/Device/Asset、CollectionPointTemplate ↔ Telemetry Key、数据单位、历史质量和故障标签均未查得，仍待安全确定开发库。
- 不应从硬编码的工业电机合成样例推断现场设备存在对应温度、电流、振动、run_state 点位。

## 5. 需继续处理的风险
1. AlarmController.Occurred 的调用者认证边界与 Originator 跨租户引用尚未完整审计；本轮只修两个告警状态写入接口，暂不变更实际设备上报路径。
2. 需要实测 JWT 401/403、跨租户同 ID、不同客户、空 Tenant/Customer、系统管理员等 HTTP 行为。目前直接控制器测试不替代真实鉴权。
3. InfluxDBStorage.LoadTelemetryAsync 中使用 DateTime.ToLocalTime() 组装 Flux range；EFStorage 的 UTC 左闭右开在 InMemory 通过，但 Influx 和实际 SQL Server/PostgreSQL 仍需独立 Provider 的时间/夏令时/聚合合同测试；当前不能直接判定存在 bug。
4. 编译中有 NuGet 安全告警（例如 Microsoft.OpenApi、SharpCompress、Snappier、SQLitePCLRaw、SSH.NET 等），应独立兼容验证和修复，不在 P0 改依赖版本。
5. 之前的预编译 Gateway 短测不是当前源代码/真数据库 1h 或 4h 长稳，也不是 PdM 线程开销证明。
