## 1. P1-07 完成内容

### 1.1 独立的安全有界历史读取

新增 IoTSharp.Data.TimeSeries/BoundedTelemetryHistoryQuery.cs：

- 可选接口 IBoundedTelemetryHistoryStorage，不改变 IStorage 的既有公开读取、持久化和 Durable Spool 合同。
- 所有查询必须提供非空设备 GUID、显式的安全点位集合、UTC 半开窗口 [begin,end)，最多 60 分钟，单设备最大行数 1～100000。
- EF Core：查询里提前执行 OrderBy(DateTime, KeyName)、Take(maxRows + 1)，由关系库 Provider 生成 TOP/LIMIT，而不是先 ToList 后检查。
- 超过最大行数时整窗拒绝，永不把被截断的采样数据用于计算“健康”。
- 执行 EF ToListAsync(cancellationToken)，将取消令牌传入数据库 Provider。

新增/局部修改的历史存储实现：

| Provider | 类型 | 实现与当前确认范围 |
|---|---|---|
| SQL Server SingleTable | SqlServerStorage 继承 EFStorage | 继承有界 EF 查询；已离线生成带 TOP 的 SQL；真实库执行计划未测 |
| PostgreSQL SingleTable / TimescaleDB | EFStorage / TimescaleDBStorage | 继承有界 EF 查询；已离线生成带 LIMIT 的 SQL；真实库未测 |
| ShardingCore (SQL Server/PostgreSQL 等) | ShardingStorage | 有界 Query + Take；**多表路由/合并与真实分片下推仍需真库验收** |
| InfluxDB | InfluxDBStorage | 安全 Flux 拼接，先明确 Device/Key/窗口过滤，再 group(columns:[])，随后全局 limit(maxRows+1)，并将 CancellationToken 传入 QueryAsync；真实 Influx Server 兼容性未测 |
| CompositeTelemetryStorage | CompositeTelemetryStorage | 仅转发到内层支持有界读取的 History Provider，永不退回原始无界查询 |
| IoTDB / Taos / SonnetDB 及其他 | 未新增有界能力 | PdM 读取器拒绝或返回 Unknown，不会回退 IStorage.LoadTelemetryAsync |

PdmTelemetryHistoryReader 现在只调用可选有界接口。对于超过上限或未实现的 Provider，拒绝窗口，不当作有效评分；没有任何新的 PLC/MES 写入路径。

### 1.2 自动取消及单设备故障隔离

- PdmWorkerOptions 新增 HistoryQueryTimeoutSeconds，默认 15 秒，允许 1～120 秒；超出配置范围禁止启用。
- 每台设备使用独立的 CancellationTokenSource，调用 ProcessAsync 时传入取消令牌；超时仅记录当前设备，继续下一台设备。
- 单设备持久化使用独立 DI Scope、独立事务；避免失败的 EF ChangeTracker 污染其他设备。
- 真实 SQLite 测试模拟第一台设备查询无限等待，1 秒自动取消，第二台仍成功计算快照。
- SQL Server/Npgsql/Influx 客户端是否及时响应取消必须在对应实际 Provider 环境复测，不能仅依据接口存在就声称所有网络请求都能立即停止。

### 1.3 严格上线门禁与 UTC 时序校验

除原有 Enabled、SchemaReady、SingleInstanceAcknowledged 和 PointMappingsApproved 外，新设两个必须明确为 true 的审批门禁：

- HistoryQueryPlanApproved：对具体查询 Provider、索引与实际 SQL/Flux、分片路由/执行计划验收后签署。
- HistoryUtcContractApproved：核对历史时间戳实际表示 UTC、边界与时区约定后签署。

注意：SQL Server datetime 本身可能丢失 DateTime.Kind。在未通过 UTC 合同门禁时，Unspecified 数据一律拒绝；仅在门禁明确通过后，才允许把已证实为 UTC 的 Unspecified 时间恢复成 UTC Kind，绝不自行按本地时间猜测；Local Kind 始终拒绝。

后端 PdM status 与 Worker 注册都遵守新增门禁。现阶段所有门禁默认 false。

### 1.4 真正 HTTP/JWT 安全测试

新增 PdmHttpJwtIntegrationTests.cs：

- 启动仅绑定随机 127.0.0.1 端口的隔离 Kestrel，使用实际 JwtBearer 认证中间件、MVC 路由及 SQLite :memory:，不启动真实 IoTSharp 实例。
- 验证未带 Token 的查询返回 401，伪造 Token 返回 401。
- 同租户/同客户获取自己设备的健康、风险记录；跨租户、跨客户的设备详情和趋势查询返回 404。
- Disabled 状态下 Authenticated 客户端可读取 status，而其他业务查询全部返回 503。
- 这些测试使用专用测试密钥/合成数据，并非真实用户登录、OIDC/生产 JWT 端到端验收。

## 4. 生产发布前的明确阻塞

1. **分库 SQL 计划**：SQL Server/PostgreSQL 的实际 TOP/LIMIT 下推、索引命中、执行超时、内存与并发；ShardingCore 不同时间分片下真实物理查询扇出。
2. **真实 InfluxDB**：混合 _field 数据类型、Flux group 后的全局 limit 与可取消查询行为、实际服务端负载和资源回收。
3. **UTC 现场核验**：SQL Server datetime/历史时区、Influx 纳秒时间、不同库的 [begin,end) 窗口语义及跨时区一致性，之后方可将 HistoryUtcContractApproved=true。
4. **真实设备配置**：Device、Asset、Product、实际采样点位、单位、预警阈值、运行/停机信号核对，真实历史数据中的空值/乱序/重复及异常时行为。
5. **长稳与吞吐保护**：正式试点库和近生产环境分别跑 1h/4h，记录业务摄取吞吐、CPU、托管/非托管内存、连接数、延迟、spool、丢包/错误/重复窗口。不要与异构 Provider 的旧指标做直接横向比较。
6. **多实例**：目前仍无分布式 lease/抢占锁，只能运维确认单实例；不得多副本生产启用。
7. **元数据库**：四张 PdM 业务表目前仅有离线初始化 DDL 预览，尚未应用真实试点数据库，需 DBA 评审及回滚策略。
8. **完整 UI E2E**：需要在受控开发环境启动真实前后端，测试登录和菜单、列表、状态、趋势、风险详情；本阶段仅通过 Vue 类型检查、Vite build 与独立 HTTP/JWT 回归。

最终结论：**P1-07 的安全查询与隔离回归代码完成；真实部署与 1h/4h 验收不能签为完成。继续保持 PredictiveMaintenance:Enabled=false。**
