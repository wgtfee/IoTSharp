## 二、关键实现

### A · 审批审计

- Review/Audit 模型具有 TenantId、CustomerId、DeviceId、ProfileId、ProfileVersion、RiskEventId、Fingerprint、Revision、创建/更新时间和审核人/原因。
- 独立 SQLite :memory: 关系模型实测；没有将新表添加到主 ApplicationDbContext/PdmDbContext，不执行生产数据库迁移或自动建表。
- CreateDraftAsync：校验待审核资料、租户和用户；相同租户/客户/规范化指纹的重复提交只保留一份草稿与审计。
- DecideAsync：要求已认证、独立审核人员、匹配 Revision 和理由；可进入 ApprovedForPlanning 或 Rejected，采用事务保存审计。提交人与审核人不能为同一人。
- 已修复 SQLite DateTime.Kind 恢复 UTC 的问题并实测回读。
- ApprovedForPlanning 仅是审核完成、可供规划，**绝不代表工单创建或下发**。

### B · 预警策略

- 创建不可变 PdmP2PolicyRevision，按租户/客户/设备规则版本进行严格作用域检查。
- 预警级别、持续次数、冷却区间等非法参数被拒绝；提交人与审核人分离。
- 状态 Draft / ReviewedForShadow / Withdrawn；ProductionEnabled 始终 false。
- 当前只是纯函数版本合同，**没有真正的配置持久化后台或生产策略发布**。

### C · 工单演练

- 依据可信的 ApprovedForPlanning 审计、相同租户/客户/审核单以及 UTC 时间生成工单规划草稿。
- 内存适配器返回幂等预览回执。相同审核记录重复预览的回执一致，跨租户/客户/审核记录隔离。
- 不配置外部工单系统 URL，不调用工单、PLC/MES 或通知系统；IsExternalOrderCreated 始终 false。
- 演练回执不能视作真正的工单执行回执。

### D · 审核台账只读 API 和 Vue

- GET /api/pdm/p2/reviews?deviceId=...&page=...&pageSize=...。
- API 要求 JWT 身份，仅从服务端 Claims 获取 Tenant/Customer，按 Device + 租户/客户过滤 Review 和 Audit，分页最多 50 条、审计 200 条。
- 在 P2ShadowPanel.vue 中增加只读 P2ReviewTrail.vue，显示维护草稿、状态、规则版本、UTC 审核时间及审计时间线，未部署时明确提示，不造虚拟记录。
- 独立门禁 PredictiveMaintenance:P2:ReviewReadEnabled 默认 false，还需要前期 P1/P2 门禁通过。默认关闭时 503，不请求审批数据库。
- 仅存在 GET 读取接口；**没有生产 POST 审批、派工或发通知接口**。
