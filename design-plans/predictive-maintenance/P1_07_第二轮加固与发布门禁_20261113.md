## 一、本轮开发

### 1. InfluxDB 防止分组前积累过多行

原查询先 group(columns: []) 后全局 limit(maxRows+1)，在执行全局限量之前可能积累较多数据；另外，布尔、整数、浮点等不同字段在合并时可能出现 Flux schema collision。

已改为：首先按 DeviceId、Key、UTC [begin,end) 过滤；把 _value 转换为 string；在各输入表分别 limit(maxRows+1)；再 group(columns: [])，最终执行全局 limit(maxRows+1)。

这样既有每个输入表的提前限量，也有跨字段全局限量。结果由 PdmFluxValueParser 按 InvariantCulture 严格解析为 bool、long 或有限 double，拒绝非法、NaN、Infinity、非数字和不可信本地时间。取消令牌在 Influx QueryAsync 和记录解码过程均检查。

注意：上述 Flux 是离线语句结构、代码和类型测试已通过。**没有实际连接 InfluxDB，不代表真实 Influx 内存/执行计划/响应时间已验证。**

### 2. SQL Server / PostgreSQL 限制单行数据体积

在既有 DeviceId、Key、UTC 半开窗口、TOP/LIMIT(maxRows+1) 的基础上，数据库侧只投影 DeviceId、KeyName、DateTime、Type、Value_Boolean、Value_Long、Value_Double。

不再把 Binary、JSON、XML、文本等大型字段读取到 PdM 进程。SQLServer/PostgreSQL 的 EF Core 离线生成 SQL 均断言不含这些字段；SQLite 实际插入 64KB 二进制和 8KB JSON 内容后，验证有界查询没有返回大对象。

ShardingCore 的真实多分表路由、物理 TOP/LIMIT 是否下推，尚未在实际分片环境测试。现有 HistoryQueryPlanApproved、HistoryUtcContractApproved 和默认禁用的 Worker 继续用于 fail-closed。

### 3. 本地 Provider 环境检查

Windows 工程机已找到 dotnet、node、sqlcmd、Docker 客户端，但没有发现 1433、5432、8086 端口的本地监听服务。Docker Desktop Linux Engine pipe 不存在，docker ps 无法列出容器。本轮不启动已有服务，不连接未知远程库，不对真实生产数据库做任何查询或迁移。
