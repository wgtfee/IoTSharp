## 1. 工作范围与实现

### P1-01：健康领域数据模型（定义已完成；迁移/生产表未启用）

新增：IoTSharp.Data/PredictiveMaintenanceModels.cs

| 领域模型 | 主要字段 | 用途 |
|---|---|---|
| PdmDeviceProfile | TenantId、CustomerId、DeviceId、ProductId?、AssetId?、Version、Enabled、WindowMinutes、MinimumCoverageRatio | 一台实际 Device 的评估配置，默认 Enabled=false |
| PdmPointPolicy | ProfileId、TelemetryKey、Unit、ExpectedIntervalSeconds、MinValidValue、MaxValidValue、WarningHighValue、CriticalHighValue、RisingTrendPerMinute、Weight、Required、Enabled | 已核对单位与阈值的点位规则，默认 Enabled=false |
| PdmHealthSnapshot | 租户/客户/设备/配置版本、UTC 半开窗口、DataQuality、RiskLevel、HealthIndex?、CoverageRatio、ExplanationJson | 离线评估快照，未知设备不写入虚构健康分 |
| PdmRiskEvent | 租户/客户/设备、EventKey、RiskType、RiskLevel、Status、First/LastObservedUtc、LinkedAlarmId?、EvidenceJson | 为 P1-04 的风险去重和解除能力提供结构；**当前无创建/上报逻辑** |

新增：IoTSharp.Data/Configurations/PredictiveMaintenanceConfigurations.cs。
- 独立 Fluent API 定义四张表、唯一键、Tenant/Customer/Device 查询索引、Profile 外键及非级联删除。
- 设备 Profile 范围内唯一：TenantId+CustomerId+DeviceId。
- 点位唯一：ProfileId+TelemetryKey。
- 快照唯一：ProfileId+ProfileVersion+WindowStartUtc+WindowEndUtc。
- 风险 EventKey 幂等唯一：TenantId+CustomerId+EventKey。

**重要部署保护**：本轮**没有**把四张表注册到主 ApplicationDbContext，也**没有**制作/应用各 Provider 迁移。原因：IoTSharp Startup 默认执行 CheckApplicationDBMigrations/Database.Migrate，缺少多 Provider 迁移时直接注册实体可能导致现有业务进程启动失败。当前 DbContext 保持与 HEAD 一致。真实建表、主 DbContext 连接和迁移必须待 P1 后续正式发布关卡经过 SQL Server、PostgreSQL、SQLite/其他已启用 Provider 的兼容性审查后统一落地。四表结构已通过隔离 SQLite 关系型数据库生成/唯一索引约束实测。

### P1-02：规则级健康评估内核

新增：IoTSharp/Services/PredictiveMaintenance/PdmHealthEvaluator.cs

- 纯计算、无 DI 后台启动、无数据库写入、无设备命令。
- 仅配置 Enabled=true 的 Profile 和 PointPolicy 才评估，必须存在必要点位。
- 多点加权规则指标 0～100（HealthIndex），综合 Risk 为 Normal / Attention / Warning / Critical / Unknown。
- 配置上限用于规则级告警，温度趋势必须持续上升且回归斜率越过阈值。
- 必需点位不可信时 HealthIndex=null、Risk=Unknown；可选点位异常时 DataQuality=Partial。
- 输出包括每个点位的质量、趋势、覆盖率及可解释原因，可转换成实体快照但**没有持久化调度**。
- FailureProbability 与 RemainingUsefulLife 保持 null；绝不将健康指数宣传为已验证故障概率/RUL。
- TenantId / CustomerId / DeviceId 不一致的整个样本批次被拒绝，防止跨设备或跨租户输入污染。

### P1-03：数据质量门禁

新增：IoTSharp/Services/PredictiveMaintenance/PdmQualityAnalyzer.cs

- 使用 DateTimeOffset 归一化 UTC，时间窗口采用 [start,end)，不会重复使用 end 边界样本。
- 区分 Offline、NotRunning、OperatingStateUnknown、Insufficient、Stale、UnitMismatch、InvalidValue、OutOfRange、ConflictingDuplicate、ExcessiveGap、SampleLimitExceeded、PolicyInvalid。
- 按事件时间排序、同时间戳相同值去重、冲突直接拒绝；记录重复与乱序数量。
- 以采样周期时间槽计算覆盖率，拒绝长连续缺口，防止突发密集采样掩盖缺失。
- 单点限制 25,000 样本、单次评估 100,000 样本；未来实际 Worker 还需要数据库层限流和资源隔离。
- 时间与物理范围、单位、阈值、权重均由现场确认，不把合成样例直接当生产配置。
