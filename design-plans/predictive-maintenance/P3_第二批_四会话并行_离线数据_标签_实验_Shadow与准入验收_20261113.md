## 三、上线阻塞和明确未完成事项

1. **真实 IoTSharp 历史 Provider**：P3 提取能力目前是严格接口 + 假 Provider 隔离测试。**还没有部署/现场测试**对接 SQL Server/PostgreSQL/InfluxDB 的真实 P3 批量离线导出；必须复用并通过 P1-07 的服务端限量、UTC、分片路由、取消/超时、执行计划与 1h/4h 长稳。
2. **现场故障样本**：只有合成测试数据，缺乏真实带维护票据的故障、正常和运行工况标签；尚无可交付的真实误报率、漏报率、模型校准、独立设备泛化结论。
3. **P3-3 监督模型**：现在仅建立人工标签数量与独立故障 Case 准入门禁；**没有训练监督学习模型，不声称故障概率、剩余寿命、预测准确率或生产可用性**。
4. **独立持久化 DB**：目前在内存 SQLite 进行了实际关系/事务验证。P3 V001 SQL Server、PostgreSQL、SQLite 脚本只是离线初始化草案；需要 DBA 评审、隔离数据库、备份/回滚及真实 Provider 并发/UTC 验收。
5. **P3 Shadow API**：使用 IPdmP3VerifiedShadowReadStore 的可信离线证据源契约，尚无经现场核验且已注册的生产实现；无可用源时拒绝返回编造结果。生产开关 PredictiveMaintenance:P3:ReadOnlyEnabled 和 :OfflineEvidenceSourceApproved 默认关闭。
6. **真实 UI E2E**：Vue 类型检查和构建通过，但尚未在真实身份登录的 IoTSharp 运行服务中执行浏览器截图验收。
7. **生产数据/硬件**：任何工单派发、告警推送、PLC/MES 控制都仍与 P3 离线/Shadow 完全隔离。
