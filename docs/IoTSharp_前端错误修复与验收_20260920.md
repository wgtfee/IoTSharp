# 前端错误修复与验收（2026-09-20）

## 结论

本轮针对上一轮完整类型检查中的 290 条错误进行修复。最终 `npm run typecheck` 退出码 0，完整前端范围 0 条类型错误；未关闭 `strict`，未缩小检查目录，未新增 `ts-ignore` / `ts-nocheck`。运行库未批量升级，仅补充与现用 uuid 9 对应的官方 `@types/uuid@9.0.8` 开发依赖。

普通警告按要求保留，包括构建工具、平台兼容及依赖审计警告；本轮不等于依赖安全审计全部通过。

## 主要修复

- 设备、资产、客户、租户、用户列表改用当前 FastCrud 的 `crudExpose` 初始化契约；回调按库声明补齐参数与返回值类型。
- 统一解析平台业务错误、Axios 错误与普通异常，避免读取不存在的 `e.response.msg` 导致二次报错。CRUD 新增/编辑/删除失败后继续拒绝 Promise，不能当成保存成功。
- 恢复 `accountApi().postAccount`，调用已有受保护的 `/api/Account/PostAccount`，不调用匿名注册接口。
- 新增用户明确输入初始密码，不再依赖固定默认密码。服务器校验目标客户，普通客户管理员只能创建本客户账号，租户管理员限本租户，系统管理员可跨租户；新账号只获 NormalUser。移除创建账号后自动切换登录会话及授予管理员角色的旧逻辑；账号、归属、角色和关系写入使用事务。
- 未修改任何既有账号、密码或角色；没有执行实际数据库创建。其它注册入口不在本轮创建接口测试范围内。
- 遥测历史的日期清空、异步图表未初始化、找不到目标曲线等情况添加保护，补齐数组和图表系列类型。
- 2D 单项数据更新使用其真实 `sourceTimestamp`，不访问仅存在于顶层快照的字段；复制场景缺少根 Asset 时明确拒绝，而非提交空资产 ID。
- 修复图标/构建版本号声明、lodash 导入、组件尺寸、字典缺失、菜单选中值、表格插槽行类型、协议配置、图编辑器连线事件、规则展开事件及登录滑块事件类型。
- 保留原布局、组件库、权限和业务边界。表单沿用现有组件，只新增必要密码输入和错误反馈；未进行页面样式重构。
