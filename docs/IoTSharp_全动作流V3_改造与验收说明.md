## 1. 当前结论

这条产线已从 Behavior V1 的整段动作序列改为 **7 套 Action Flow V2、90 个节点、0 条旧 Behavior**。三维运行器按图中的连线、条件、参数逐节点执行，不再把节点当作计时演示。修改延时、条件变量、连线后改变真实轴运动和执行时间，已有专项验证。

**本次动作流专项测试、真实组件离线整线和前端生产构建已通过；实际浏览器操作、数据库保存/发布/重开验证尚未完成。** 本轮审计确认的 8 项漏洞均已修补并完成对应回归，详见 3.2。数字孪生范围的类型错误为 0，但全项目类型检查仍有其它模块的 290 个错误。主测试项目此前被其它依赖的安全检查阻断，本轮未重新完成该项，不能把专项通过说成整个仓库验收通过。此前浏览器控制连接失败，不能使用之前的登录答复推断当前登录态或发布结果。代码更新不会自动修改数据库里的旧草稿或历史发布版本。

保持原来的 98 个组件、2 条路线、9 个工作点、9 个物料槽位、44 个执行机构及 50 小托盘。新增的分流判定停车点只切分现有中心线，不增加一条辊道，也不移动外检上方双排及其上方单排空回流。

## 2. 哪些内容由图控制

| 动作图 ID | 工艺职责 | 实际完成依据 |
| --- | --- | --- |
| `drawing-flow-load` | 左右丝车轮换、备料、腕部姿态、接近、夹紧、挂接、提升、变距、放入双排空托、回位 | 实际库存、12 托批次、轴到位、物料挂接及释放 |
| `drawing-inspection-flow` | 等待外检到位、外检节拍、标记 inspected、放行 | 实际工位当前托盘及图内延时 |
| `drawing-flow-routing` | 判定是否载料、选择空回流或套袋干线、按 A/B 选择套袋出边 | 当前批次实际丝锭数量、托盘分组、逐托盘路线选择 |
| `drawing-bag-a-flow` | A 套袋节拍、标记 bagged-a、放行 | A 工位实际托盘及图内延时 |
| `drawing-bag-b-flow` | B 套袋节拍、标记 bagged-b、放行 | B 工位实际托盘及图内延时 |
| `drawing-flow-stack` | 六件收料、等待木托、放丝锭层、取隔板、放隔板、安全退回、放行空托 | 真实工具/槽位、木托容量、联锁、安全位置 |
| `drawing-flow-dispatch` | 等待木托、校验 48 丝锭和 8 隔板及双夹具退回、出料 | 已完成堆叠和图内安全联锁 |

图之间并发推进，通过工位所有权、共享语义状态和联锁协调。每个图内部按节点连线执行有界循环。

“动作流驱动”不等于没有底层代码。路径插值、防碰撞、执行机构运动学、夹具挂接、物料归属和库存操作仍是通用执行器；它们不决定这条产线接下来做哪一道工艺。新场景复用原运动学代码的单动作接口，但不运行 V1 工艺调度。

组件几何、标定和初始图由模板生成；生成后作为场景数据保存，可以在设计器修改。不是每次运行时重新用模板覆盖用户图。

## 3. 执行与安全约束

1. `executionTarget: scene` 的图只能由真实三维场景执行桥启动；独立计时调试器不能代替它完成设备动作。
2. `WaitStation` 获取工位当前托盘批次所有权；`CompleteStation` 检查批次未变、完成组一致、夹具无残留物料，才能放行。
3. 外检、双套袋的节拍和物料标记在图中，不再由工位固定周期自动放行。
4. `SelectRoute` 只调整该批次尚未经过的岔口决策，不回退或重走已通过路线，不传送模型位置。
5. 图故障会暂停整线，不能单独重启输送带绕过故障；需排除原因后复位或重新运行。
6. 禁止启用中的 V1 序列与真实场景图混用，避免双重控制或静默忽略旧动作。
7. 三维图的运行模式只允许 simulation。服务端拒绝把这种图当作 Live 设备命令启动；没有伪造 PLC ACK。
8. 三维节点面板只显示已接通的能力。单图并行分叉/汇合、子流程、人工确认、设备握手等未完成三维适配的节点不允许在此模式下编译通过。七套图之间并发不受此限制。
9. 保存端重新校验与编译，不能信任客户端提交的 Hash。错误引用、断开的必需端口、空条件、无效变量、非法模式、无适配节点等返回诊断。
10. 节点 `speedRatio` 已传递到真实执行轴；修改速度系数改变运动耗时，不改轴的基础标定速度。未设置时为 1，复位清除上次动作的倍率。
11. 直线轴支持米和毫米；姿态捕获、TCP 坐标换算、目标和速度都使用统一换算。转轴只允许弧度/角度，夹具只允许布尔单位，前后端均拒绝不匹配单位。
12. 木托经过直角弯不再瞬间旋转整垛物料。仿真中按转向速率连续趋近路线朝向，默认每秒 90 度；暂停时保持姿态。此项未修改原辊道中心线，不代替现场转向机构建模或全机械干涉检测。
13. 越程目标直接拒绝，不做边界截断；故障说明包含轴名称/ID、请求值、单位和允许行程。动作流进入 Faulted，不发送完成信号、不继续下游。统一轴入口覆盖动作流、旧原语、手动和遥测；非法请求保持当前位置和上一个合法目标，故障时不继续插值。
14. 示教姿态、桁架多轴、回零和变距批次先校验整组目标再发命令。机器人 IK 按配置的关节行程筛选等价解；位置或工具姿态不可达立即报错，不等超时，也不把无解目标推到边界。动作流禁止通过直接拖动模型节点绕过运动学。
15. 有硬限位的旋转轴沿真实轴坐标运动，不按跨限位的最短角走；没有上下限的连续旋转轴仍可用最短角插值。精准边界值允许执行。遥测的关闭插值选项不再使动作流瞬移。

### 3.1 条件控制的物料交接

动作流条件可引用槽位现存数量/剩余容量、工具是否为空/持有数量、夹具是否闭合和 TCP 接触是否就绪。运行器现场计算这些只读状态；`SetState` 不能伪造它们。普通槽位取料不自动补出库存，补料由显式 `PrepareSlot` 控制。

原生图的 Attach/Pick 要求真实物料、有效 TCP、夹具闭合和接触成立。Place/Detach 要求目标容量足够、物料对齐，先完成真实对象交接，再在同帧打开对应夹具；批次最后一件失败时，整批不部分释放。持料中单独 GripOpen 被拒绝，不能空中松爪。暂停保持挂接；复位恢复已捕获的来源库存。

### 3.2 2026-09-19 安全审计的 8 项修补

| 审计问题 | 本轮修补 | 验证重点 |
| --- | --- | --- |
| 联锁撤销后仅流程等待，轴仍向旧目标运动 | 在轴插值前重新检查当前节点联锁，立即将该 Actor 的仿真运动轴目标保持在当前位置；夹具和挂接保持不动。恢复许可后由当前图节点重新下达原目标 | 联锁撤销后连续 20 帧位置不变，恢复后到原目标并正常完成 |
| 运动超时可 skip/retry/错误分支绕行，造成假完成 | 三维安全节点仅允许故障停机；前端、服务端和执行器三层拒绝绕过。异常时撤销当前运动目标，整线保持 | 绕过编译器传入旧非法计划，运行器仍 Faulted，无完成/跳过/自动重试事件 |
| 缺失、过期值被当成 false，字符串 false 被当成 true | 未知值不参与放行；布尔条件仅接受 true/false、1/0 及对应字符串，字符串忽略大小写与首尾空格 | 缺失、过期、null、NaN、不等于条件及字符串布尔专项 |
| SetState 可覆盖真实绑定许可 | binding: 命名空间、已有 bindingId、material/ 和 station. 反馈只读；同时校验 onStartState/onCompleteState，读取绑定优先于流程语义值 | 普通引用、带空格引用、两类隐式状态赋值均拒绝 |
| 工具/来源/目标槽位物料类型不一致仍可交接；异物不占容量 | 取放前校验槽位声明、实际物料类型、工具允许类型；普通槽位所有实体均占容量 | 错误类型保持原归属；普通目标有异物时容量为 0 |
| risingEdge/changed 没有更新前值，稳定高电平重复触发 | 每仿真帧统一采样并更新前值；首次有效值、失效后恢复只建立基线，复位清空历史 | 真实上升沿只触发一次，稳定高电平不重复，复位和未知恢复不伪造边沿 |
| 不同物料对象可使用相同业务 ID | 每批交接前检查 ID 非空、无首尾空格、批内唯一，并检查场景内该批 ID 无重复；整批预校验后才改变归属 | 批内重复、跨槽重复、缺失 ID 均拒绝，不发生部分挂接 |
| Attach 不写类型时错误回退为 payload | 先采用来源槽位声明的 payloadType，来源未声明时才采用通用默认值 | 省略类型仍能取到正确的来源库存 |

安全节点包括运动/姿态/回零、夹爪、取放/挂接、备料、互锁等待、工位等待/放行、物料标记和路线选择。上述节点不能配置超时跳过、自动重试、补偿节点或 failure/timeout 出边；旧场景若使用这些配置会明确报错，不会悄悄改写。普通 Delay 等非安全节点保留原策略。

普通槽位按全部实体计容量；木托上通过堆叠模式共享空间的丝锭槽位与隔板槽位仍按各自类型计容量，保证 48 丝锭 + 8 隔板不会被当作同一种物料计数。这是已声明堆叠模型的容量规则，不是忽略其它物料。

本节的停止/恢复接口仅作用于仿真轴，不发送 PLC 指令，也不代表真实设备的安全 PLC、急停或减速度控制已经接入。外部执行轴适配器必须同时提供保持/停止接口，缺少该接口时运行器拒绝初始化。正常人工暂停仍保留原目标和挂接，继续时不丢失进度。

## 4. 设计器使用方式

### 4.1 新建独立 V3

三维场景设计器 → **更多 → 按确认图新建 · 全动作流 V3**。

选择根 Asset 后，“创建并入库”沿用组件资源注册、对象资源绑定和场景创建接口。生成的本地模板本身不是数据库场景。

进入“分屏”，选一个动作图，编辑节点参数、联锁、槽位、变量或输出连线，然后点击 **按当前图重新运行**。画布高亮和状态来自三维运行器，不是另一套假执行器。

修改动作图会暂停当前预览。需要重新加载图后再运行，不能在旧执行计划上假装应用编辑结果。

### 4.2 升级已经保存的独立图纸工艺 V2

选中原图纸工艺草稿后，更多菜单提供 **当前图纸工艺升级动作流（保留布局）**。只有组件、路线和工艺工作点均符合已标定图纸场景时才显示。

- 先导出备份；此操作以标准七套图替换原抓丝、码垛和出料序列，不是对任意自定义旧步骤作无损翻译。
- 保留场景 ID、根资产、对象、模型变换、资源/设备绑定、轴、工具、槽位、Pose、工作点及原路线中心线。
- 保留原外检/套袋的 cycleSeconds 和完成物料阶段，把它们迁入 Delay/MarkMaterial 节点。
- 只增设原中心线上的分流判定停车点，替换相应的旧岔口规则；不新增一条物理输送通道。
- 仅修改本地草稿，**不自动保存或发布**。检查运行后，先“保存草稿”，再“发布”。
- 已有三维动作图、存在其它启用旧设备动作、必要工位缺失等情形会拒绝升级，避免覆盖已编辑内容或静默停用设备。
- 旧 V19 或其它场景不会仅因名字相似而获得升级入口。

旧的通用 “V1 一键转换”仅生成独立调试图，不能替代上述整线升级；界面已明确提示其范围。

### 4.3 改图的方法

- 流程执行目标选择“真实三维联动”。新建空白动作图默认采用该模式。
- “流程变量”可新增、删除变量及修改类型/初始值，Condition 和 SetState 引用这些变量。
- Condition 可新增/删除多行条件，切换 AND/OR，并选择实际物料状态、变量或绑定字段；嵌套组合条件保持原配置，通过受控 JSON 编辑。
- 选中节点后可修改输出端口和目标节点，或删除连线。条件必须有 true/false，循环必须有 repeat/done。
- 节点可选择执行对象、TCP、工作点、槽位、联锁、数量、接近偏移和速度。变距网格等高级字段仍可通过 Config JSON 调整。
- 三维联动面板提供整线启动、暂停、继续、复位；未接入的单节点断点入口在该模式下隐藏。
- 新增控件补充了可读名称，变量对话框沿用系统组件交互；键盘和实际浏览器可用性仍需页面验收。
