## 2. 已确认的物理布局与流向

图纸像素映射：`X = (像素 X - 800) × 0.08`，`Z = (像素 Y - 570) × 0.08`，Y 为高度。它是图纸比例映射，不能作为现场测量尺寸或设备选型依据。

| 区域 | 布置与流向 | 本次约束 |
| --- | --- | --- |
| 抓丝机器人前 | 底部双排，小托盘由左向右 | 两排都向外检，不相向运行 |
| 外检 | 右端上行后，由右向左通过外检 | 不额外增加外检右侧直达套袋捷径 |
| 外检上方 | 转弯上行后双排向右，到右侧套袋分配区 | 两排都是载料前进通道 |
| 这组双排再上方 | 单排空托回流，由右向左，左端下行 | 回到抓丝机器人，不放在外检下方 |
| 双套袋 | 上、下两台均从右向左输送 | 按通道分配，完成后才放行 |
| 顶部及左侧 | 顶部向左，桁架下方双排向下 | 载料托盘在桁架处按双排六件收料，空托继续回机器人 |
| 木托大辊道 | 独立路线，通过码垛位后出料 | 木托未满 48 件且 8 张隔板时不放行 |

内部短缓存、环形区域和设备模型仍保留。主工艺选择已确认的主通道，不代表所有内部支线都已经有生产业务规则。

## 3. 可执行工艺

### 3.1 抓丝、双排上料

1. 两侧旋转台/丝车按来源物料槽位调度，只有真实库存和停车批次就绪才开始。
2. 双排各 6 个空小托盘沿路线依次停止，共 12 托；没有视觉合并成一个托盘。
3. 机器人调整腕部和夹具，移动到实际丝锭接触面后抓取，物料保留原实体 ID。
4. 夹持物随真实执行机构和抓位节点运动，不在取放瞬间重建替身或跳到目的地。
5. 双面丝车每面 18 件，12 件抓取后的 6 件尾批按两排均衡放置；允许未装丝锭的小托盘继续流转。
6. 放料按最小位移的一对一抓位分配；先展开行间距，再调整列位置，避免按数组次序映射时夹头交叉。
7. 机器人回到安全姿态后，工位完成组才放行该批小托盘。

### 3.2 外检、双套袋与空回流

- 外检、套袋只接收实际挂载物料的托盘；仿真节拍完成后为该物料记录 `inspected`、`bagged-a` 或 `bagged-b`。
- 空托按实际物料数量在岔口选择空回流；载料托盘选择套袋方向。
- 抓放改变载料状态时，只重规划尚未经过的岔口。已经进入的路段锁定，不能倒退或被重新规划到其他位置。
- 两台套袋机分别加工、独立完成，不通过减少实体数量来实现合流。

### 3.3 桁架、隔板、木托

- 双排各 3 个载料托盘到位，共 6 件，桁架按当前托盘实际物料取料。
- 丝锭夹具与隔板夹具使用各自所属的直线轴，工作点绑定相应 TCP。
- 码垛为每层 2×3、共 8 层，即 48 件；每层放置 1 张隔板，共 8 张。
- 丝锭夹具先安全退回，隔板夹具再取放；隔板补料之后重新计算接触高度，不沿用上一次库存高度。
- 目标是当前到位木托，不能退回上一托的完成状态或残留引用。
- 木托完成丝锭数量、层间板数量及动作安全退回后出料，再补下一托。

隔板和木托在本模板中都是 5.6×2.8 m 的图纸比例尺寸。这不是实际隔板采购尺寸。图中没有独立天盖、缠膜、贴标生产段，本次没有追加这些工序。

### 3.4 暂停、复位、异常

- 运行暂停时，路线、物料和由仿真动作驱动的执行轴同时暂停。
- 复位恢复初始 50 空托盘、来源物料的 ID/位置、旋转台基准姿态、轴位置和工位完成计数。
- 不移除机器人原有的固定挂载节点；只移除运行时建立的物料载体。
- 已完成木托隐藏出料不等于删掉其成品记录；不计入下一托的活动工位占用。
- 动作报错保持故障状态，复位后重试，不每帧重复执行失败步骤。

## 4. 设计器入口与入库发布

1. 启动当前版本前后端，登录 IoTSharp。
2. 进入 **3D 场景设计器 → 更多 → 按确认图新建 · 图纸工艺 V2**。
3. 选择正确的根 Asset（例如用户实际管理的“包装”产线 Asset），填写新名称。不要对旧 V19 使用替换模板操作。
4. 创建动作会通过授权 API 注册/取得 10 类组件资源的真实 GUID，再将 98 个组件实例及 Asset 引用一起写入新场景草稿。
5. 打开“运行预览”，点击运行，检查默认速度下托盘、抓丝、套袋、码垛、隔板和木托放行。
6. 保存草稿、发布，随后从场景中心打开**新场景的最新发布版本**。不要沿用旧 V19、`version=9` 或模板 ID 的链接。

必须通过的数据库验收：

- 创建响应返回真实 sceneId；重开页面可以读取同一草稿。
- 所有组件 `resourceId` 是平台返回的 GUID，根 Asset 及对象 Asset 绑定保留。
- 发布后出现不可变发布版本，场景中心状态是“已发布”，不是“发布后已修改”。
- 打开该新版本后，4 组编排、9 个槽位、轴绑定以及新路线仍存在。
- 未登录、越权、资源注册失败时不能伪装创建成功；不得用直接写 SQL 绕过权限。

## 5. 新配置合同及编辑约束

| 字段 | 作用与限制 |
| --- | --- |
| `process.batchArrivalMode` | 新场景用 `route-aligned`；未配置/legacy 场景保留旧路径 |
| `process.batchSize/batchLaneSize` | 1～99 整数；同设备各通道容量和必须等于总批次 |
| `process.materialAdmission` | `any`、`empty`、`loaded`，按实际物料实体判定 |
| `process.materialStageOnComplete` | 完成阶段，非空、最多 128 字符 |
| `route.replanUpcomingJunctions` | 布尔值，只支持折线；锁定已经过的岔口 |
| `toolFrame.cartesianActuatorIds` | 最多 3 个无重复、属于该设备的直线轴 |
| `action.alignPayloadGrid` | 只用于 moveTo，来源/目标槽位必须二选一；抓位数 1～12 |
| `initializer.transportUnitProperties` | 只允许文本、有限数字、布尔值；不接受嵌套对象或脚本 |
| `initializer.simulationHideAtExit` | 布尔值，仅用于离线出料展示 |

前端即时诊断、服务端独立诊断均已补齐。配置错误应返回具体位置，不允许仅依靠前端检查。新增编辑控件沿用现有界面，补有可识别的文字标签；工位类型列表补齐“木托码垛等待”。
